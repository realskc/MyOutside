# 参考：外部资料

这里记录 MyOutside 以外、值得留下来的东西：竞品、互补品、开源技术项目，也包括**领域资料**——人物、作品、版本、数据集、某个网站或平台能查到什么，以及其他任何值得参考的东西。工作中搜集到的、值得记录的资料都放进来（作者，2026-11-11）。作者尤其想多看新的 agent 项目：它们的 agent 设计是怎样的、有什么好的地方。

**为什么要记**（作者，2026-11-11）：初衷是换 agent 的时候不用重新查资料，资料还可以越积越多、越来越有用。所以 references 里不能有没标注的错误——错误越积越多，就不一定是正效果了。

**什么时候记**：随查随记。为了做事去查的外部事实（例如给纯蓝挑训练数据时查的声库版本、歌曲的投稿日期和制作人员）也算，不要只留在对话或试验记录里；以后可能还用得上的就记；拿不准值不值得记时也记（作者：资料随便记）。发现记错了就改。

应用专属的外部资料放在 `apps/<app>/references/`，格式与这里相同；主 `references/` 只放跨应用 / 平台级资料。

每个对象（产品、项目、人物、作品、数据集……）直接一个 Markdown 文件，放在本目录下，文件名就是它的名字（例如 `Obsidian.md`）；不再为单个对象建子目录。条目多的应用可以按类别分目录（例如 `apps/66CCFF/references/singers/`）。

- **资料**：文件名就是它的名字；
- **我们的想法**：文件名用 `<项目名>-thoughts.md`（例如 `Obsidian-thoughts.md`）。还没有想法时可以没有这个文件。

和它密切相关的条目可以各自成文件，用文件名区分，例如 `LLM-Wiki.md`；一个项目有多个资料文件时，用 `<项目名>-<主题>.md`。

## 资料

- 调研出来的事实：它是什么、怎么做的、怎么收费……
- agent 可以自行调研、补充、更正，也可以自行新建（作者：资料随便记）。
- 只写事实，不写评价；每条注明来源（链接）；文件开头写最近一次核对的日期——外部的东西会变，资料可能过时。
- 不是直接查到、而是推断出来的（例如按声库发布日期推断一首歌用的哪个版本），标「推断」；来源之间有矛盾的，两边都记下来，查清了再写结论。

## 我们的想法

- 对它的看法：有什么值得借鉴、有什么新奇的、能不能被我们使用……
- 和 user spec 一样，**只记作者说的，或者作者明确认可的 agent 的说法**。agent 自己想到的不记；拿不准作者是否认可时，先问。
- 作者认可的 agent 说法，注明「agent 提出，作者认可」。
- 「明确认可」指作者说了「说得好」「有道理」这类表示赞同的话；没有表态不算。（agent 提出，作者认可）
- 某个想法变成了对 MyOutside 的具体预期时，写进对应的 spec 文档，并链接回这里。
