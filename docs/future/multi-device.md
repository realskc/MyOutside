# 多端（电脑 + 手机）技术设计

> 未实施。方案选择与理由见 D-0013（云端内核）、D-0012（运行时无关）、D-0020（移动端用 Web 界面）；作者的预期见 `user-spec/platform.md`「多端」。
>
> 开发用的临时 LAN 预览（Electron 主进程内 HTTP 宿主）见 D-0072，它不是本方案。

## 1. 落地后的部件分工

| 部件 | 位置 |
|---|---|
| 界面（外壳 + 各子应用界面） | 每台设备本地 |
| SDK / 传输 | 本地；传输从 Electron IPC 换成 WebSocket |
| 内核（队列 / 事务 / 路由 / 迁移 / DataVersion） | 云端 |
| 子应用后端 | 云端（与内核同处） |
| 数据库 + 文件仓库 | 云端 |
| 设备能力（音频、通知、文件选择） | 本地（始终） |
| 身份 / 登录 | 云端（哪怕单用户也需要一点） |

手机端 = 同一套 Web 界面（PWA / Capacitor 壳）+ SDK，薄客户端，不需要本地内核。

## 2. 现在就要遵守的约束（D-0012）

1. SDK 与传输「可换传输」：调用面（`outside.call`）不假设与内核同进程；
2. 设备能力只放在前端与外壳（发音、通知、文件选择等不进后端）；
3. 内核、契约、子应用后端不 import Electron / 浏览器专有 API；
4. `kernel-node` 适配器将来在云端直接复用——同一套内核代码，本地与云端同构部署。

## 3. 缓存 / 离线（后置）

- 按子应用定制：每个应用缓存什么、怎么缓存各不相同（例：vocab 缓存待复习卡片 + 排队提交评分）；
- 设备端缓存可以是任意简单存储（IndexedDB 等），不需要 SQLite；
- `kernel-web`（SQLite WASM + OPFS）只在「本地优先」方案下才需要，降级为备件。

## 4. 实施时的待办
