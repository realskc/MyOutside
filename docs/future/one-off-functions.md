# 临时函数（One-off Functions）

> 状态：设计草案（2026-10-01）。
> 上游：requirements.md §2.6 / §2.7、vision.md §5。

## 1. 定位

临时需求是一等公民。其标准形态是**临时函数**：一段一次性代码，用来表达现有应用接口表达不了的临时操作（例：手工修正某个自动计算的字段、批量导入既有数据）。

临时函数由用户在 builder 子应用中以自然语言发起（对 builder 而言就是一次 tool call）。

## 2. 规则

1. **软门槛**：发起前向用户说明并获得确认；确认内容包含**作用域**。
2. **作用域**：
   - 作用域内（用户点名的应用）：允许**绕过其 API、直接读写它们的表**（数据库层的表约束仍然生效）；
   - 作用域外：一律走对方的 API（`tx.call`），不得直写。
   - 实践建议：能调 API 的地方先调 API，直写只留给 API 表达不了的字段；直写后若应用提供重算 / 修复 API，应调用它恢复不变量。
3. **单次执行**：执行一次后**立即注销**——无论成功或失败。要重试就重新注册；源码已进日志，函数文件可随之删除。
4. **自动留痕**：内核自动写一篇 markdown 到 agent-log：意图、完整源码（代码块）、参数、作用域、影响行数、结果（含失败原因）。
5. **无晋升**：临时函数不可永久保留；若要永久化辅助函数，只能由 builder 显式发起「永久修改」工具调用，经用户同意后走正常修订流程（requirements §2.7）。
6. **经内核执行**：仍走串行队列 + 事务；内核未运行时不允许直接改库。

## 3. 接口（示意）

```ts
// builder 侧的 tool call：注册 → 执行 → 注销 → 写日志，一步完成
oneoff.run({
  intent: "手工修正：把 word#42 的 autoScore 改成 0.9",  // 必填
  source: "<代码字符串或文件路径>",                       // 必填，源码进日志
  scope: ["vocab"],                                       // 允许直写的应用
  params: { wordId: "42", score: 0.9 },
});
// → 事务内执行 → 立即注销 → 日志落盘 → 返回结果
```

## 4. 技术要点（已验证可行）

- **子应用不可调用**：临时函数注册在独立命名空间（如 `#oneoff.*`），`outside.call` 的路由不解析它；
- **执行完消失**：注册是内存态，执行后立即注销（成功或失败都一样）；
- **源码留档**：注册时内核读取文件 / `fn.toString()`，写进日志；
- **作用域检查**：直写时校验目标表的归属是否在作用域内，超出即拒绝。
- **诚实提醒**：临时函数运行在内核进程里，理论上具备 Node 的全部能力；控制手段 = 软门槛 + 源码留痕 + 用户过目。将来若要更硬的隔离，可考虑受限子进程执行（后话）。
