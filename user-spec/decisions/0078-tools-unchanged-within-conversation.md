# D-0078 对话中不改动工具定义；轮数用完时用 tool_choice = none

- 状态：有效
- 日期：2026-10-28
- 决策者：作者（不改动工具定义、用 tool_choice）；agent（追加的说明、仍然调用时的处理）
- 服务于：
  - 作者预期：[platform.md「平台 AI」](../platform.md)（对话过程中不改动工具定义）
  - 上游决策：[D-0059](0059-no-tool-choice.md)（思考模式下不用 required / 指定工具）、[D-0060](0060-tool-loop-ends-without-tool-calls.md)（工具循环在模型不调用工具时结束）

## 决策

- 工具循环的每一轮都带同样的工具定义；
- 到了最多轮数的最后一轮：请求设 `tool_choice: "none"`（工具定义照常带上，只是这一次不许调用），并在对话末尾追加一条说明（默认「已到最多轮数：这一次不能再调用工具了。请直接回复：说明已经做到了哪里、还有什么没做完。」，调用方可以换）；这条说明记在这一轮上（`round.note`），轨迹里能看到；
- 模型在这一轮仍然调用了工具（理论上不会）：不执行，补上「没有执行」的结果保证消息合法，以 `max_rounds` 结束；
- 平台 AI 的 `platform.ai.chat` 增加 `toolChoice`：只接受 `auto` / `none`，带工具时透传为 `tool_choice`。

## 理由

原来的做法是最后一轮拿掉工具定义。哲野试验台的一次试跑里，三个跑到上限的环节在最后一轮都几乎完全没命中缓存（17.7 万 tokens 只命中 384），三轮共花约 0.75 元，占那次试跑的近两成；模型还把它内部调用工具的格式当成文字输出（`<｜｜DSML｜｜ …>`），或者说完「下面逐一修改」就被截断。

`tool_choice: none` 在思考模式下可用（DeepSeek 文档：只有 required 与指定工具不支持）。真实接口验证（`pnpm ai:check`）：最后一轮输入 2031 tokens，命中缓存 1792；模型直接回复，没有输出工具调用的格式。

## 什么时候应该重新考虑

- DeepSeek 对 `tool_choice` 的支持变化时；
- 出现「这一轮只许调用某几个工具」的需求时（只能靠提示词，不能改工具定义）。
