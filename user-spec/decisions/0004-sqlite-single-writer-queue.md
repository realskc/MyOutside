# D-0004 数据存储：SQLite 单文件，内核是唯一写入者，写操作串行排队

- 状态：有效
- 日期：2026-09-30
- 决策者：讨论
- 服务于：
  - 作者预期：[platform.md「数据一致性」](../platform.md)（跨应用操作全部生效或全部不生效；结构上不会出现写冲突）

## 背景

子应用之间要原子地交换数据（「一次事件多处落账」），同时不能依赖开发者自觉来避免并发冲突。

## 决策

- 全部持久数据放在一个 SQLite 数据库文件里（大文件的实体放磁盘目录，数据库只存元数据）；
- **内核是唯一写入者**：子应用不直接访问数据库，统一经内核；
- **所有写操作在内核里单队列顺序执行**，每个写操作是一个数据库事务；跨应用落账在同一个事务里完成；
- 每次提交后全局数据版本号（DataVersion）加 1。

## 考虑过、没有采用

- 两阶段提交 / 分布式事务：单进程单库下没有必要。
- 子应用各自持有数据库、靠同步合并：冲突无法在结构上消除。

## 代价

- 写吞吐受限于单队列（个人软件场景下可以忽略）；
- 事务内不能做异步操作（导致 D-0007、D-0008）。

## 什么时候应该重新考虑

- 写吞吐成为真实瓶颈；
- 多端改为「本地优先」方案（见 D-0013）。
