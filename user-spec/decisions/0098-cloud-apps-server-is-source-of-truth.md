# D-0098 学英语、对话、围棋、哲野以服务器为准：真实数据合并后搬进作者的 realskc 账号，本地 Electron 不再装它们

- 状态：有效
- 日期：2026-11-14
- 决策者：作者定了「以服务器为准，本地留个备份然后清理」和「上传到 realskc 账号，不要 admin」；合并与清理的做法是 agent 定的
- 服务于：
  - 作者预期：[platform.md「分发与隔离」](../platform.md)（本地 app 理论上是连到服务器的客户端，数据在服务器上）、[platform.md「多端」](../platform.md)（个人数据多设备共用）
  - 红线：[AGENTS.md「红线」](../../AGENTS.md)第 1 条（不能破坏作者的生活数据）
  - 上游决策：[D-0091](0091-one-database-per-user.md)（每个用户一个库）、[D-0092](0092-backup-to-r2.md)（备份）

## 背景

这四个子应用只用数据库和平台 AI，已经上了服务器（docs/future/web-version.md §1）。作者两台电脑（Mac、ThinkBook）上的 Electron 里各有一份它们的数据，各写各的。作者要把两边合起来放到服务器上，之后以服务器为准。

## 决策

**合并**（2026-11-14 做的一次，作者确认后上传）：

- 两边的库都只读：ThinkBook 是作者用 `VACUUM INTO` 拍的快照，Mac 由 agent 用同样的办法拍；
- 用现在的代码建一个全新的库（和服务器第一次打开时一样：建表、跑迁移、写参考词表），再把两边的数据放进去。两边的表结构、迁移完全一样，主键没有重复，直接合在一起：学英语 42 张卡片、对话 6 个会话（26 条消息、13 条实验记录）、围棋 4 局棋谱、哲野 1 次试跑；用量记录按时间重新编号放在一起；
- 不搬的：两边「当前这一局」围棋（都是没开始的空棋盘，座位绑的是旧浏览器；作者：丢了也无妨）；两边的 API key（各自电脑的钥匙串加密的，换了机器解不开；服务器用共用的 key，D-0097）；纯蓝、网易云下载（留在本地）；
- 合并后检查：行数等于两边相加、消息都有所属的会话、参考词表和两边一致、完整性检查通过、用现在的代码打开能读出四个应用的数据。

**上传**：放进作者自己注册的 `realskc` 账号（作者：不要 admin）。上传前做 R2 备份、在服务器本地再留一份；停服务几秒换库；原来那个账号里试用时的空棋盘另存在 `/var/backups/myoutside/`。

**本地**：Electron 默认不再装这四个子应用，只装要用本机的纯蓝和网易云下载；冒烟测试（在数据副本上）和开发时设 `MYOUTSIDE_ALL_APPS=1` 仍装上全部。本机库里这四个子应用的数据，用一次性脚本 `scripts/cleanup-local-cloud-apps.mjs` 清掉：先把整个库备份到库旁边的 `backups/`，再删它们的表、迁移记录和用量记录。脚本要在 MyOutside 完全退出后运行（库旁边有 `-wal` 文件就拒绝）。

## 考虑过、没有采用

- **本地留着这四个子应用、只是不用**：两边又会各写各的，作者要的是以服务器为准。
- **只隐藏不删数据**：作者要「本地留个备份然后清理」；备份已经有了（本地 `backups/`、ThinkBook 的快照、服务器、R2）。
- **按某一边为主、只补另一边缺的**：两边没有重复，没有必要。

## 代价

- 在 Mac、ThinkBook 上用这四个子应用要开浏览器（myoutside.org），本地 Electron 里看不到它们，直到 Electron 变成连服务器的客户端。
- `realskc` 不是管理员：作者自己的 AI 用量也受每周 ¥20 的限制（D-0097）。
- 冒烟测试在 Electron 里检查这四个子应用的界面，而作者实际是在浏览器里用它们；把浏览器检查并进冒烟以后再改（docs/future/web-version.md §8）。

## 什么时候应该重新考虑

- Electron 变成连服务器的客户端时（platform.md「分发与隔离」），这四个子应用经它从服务器打开；
- 某个子应用需要离线用时。

## 收尾

Mac 和 ThinkBook 都运行过清理脚本以后，删掉 `scripts/cleanup-local-cloud-apps.mjs`（AGENTS.md：不留永久的迁移代码）。
