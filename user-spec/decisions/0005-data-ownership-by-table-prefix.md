# D-0005 数据归属：按应用划分表，禁止跨应用共用表

- 状态：有效
- 日期：2026-09-30
- 决策者：讨论
- 服务于：
  - 用户预期：[platform.md「数据归属与子应用之间的连接」](../platform.md)（每一份数据都有唯一确定的所有者）
  - 上游决策：[D-0004](0004-sqlite-single-writer-queue.md)

## 决策

- 每张表归属唯一 owner（某个子应用或平台）；**禁止跨应用共用表**；
- 子应用通过宿主提供的数据助手（AppDb）访问数据，助手自动给表名加 `应用id__` 前缀，因此子应用在结构上只能碰到自己的表；
- 子应用在 `owns` 中声明自己拥有的表；
- 数据库迁移只操作自己的表，由宿主在启动时按注册顺序执行。

## 考虑过、没有采用

- 共享数据（直接读写他人的表）：耦合点变得隐蔽，无法剥离。
- 客户端提交批次计划（batch）：违背边界原则，已废弃。

## 代价

- 迁移里的 `exec` 逃生口可以绕过前缀，目前靠自觉；`owns` 声明目前不做强制校验。

## 什么时候应该重新考虑

- 数据不再以「表」的形式存储时（用户原话：以后数据不一定用表的形式存储）。
