# D-0075 凭据用系统钥匙串加密保存

- 状态：有效
- 日期：2026-10-27
- 决策者：agent（作者要求「搞一下」）
- 服务于：
  - 作者预期：[platform.md「平台 AI」](../platform.md)（密钥由平台保管，子应用拿不到）
- 取代：[D-0019](0019-api-key-in-platform-settings.md) 中「SQLite 明文存储」的部分

## 决策

- 凭据类平台设置（目前是 DeepSeek API Key）在平台设置表里只存密文：`{"$encrypted": "<base64>"}`；
- 加解密由运行环境提供：Electron 用 `safeStorage`——macOS 上加密密钥由系统钥匙串保管（钥匙串里的「MyOutside Safe Storage」），Windows 上是 DPAPI；内核只依赖一个「加密 / 解密」接口（`SecretCodec`），不依赖 Electron（D-0012）；
- 启动时把已有的明文凭据改为密文；系统不支持加密时退回明文保存；
- 解密失败（钥匙串拒绝访问、换了系统账户等）时，平台 AI 报 `PRECONDITION`，提示在设置里重新填写；
- 需要真实密钥的开发检查（`pnpm ai:check`）跑在 Electron 里（不显示窗口、在真实数据的临时副本上），密钥照常从钥匙串解密、只在内存里使用；不经 Electron 的脚本解不开密文，也不通过环境变量、命令行传递密钥（会留在终端历史、对话记录里）。

## 理由

数据库文件被复制、同步到别处，或者被别的程序读取时，密钥不会随之泄露；任何子应用本来就读不到凭据（D-0053），这一条补上的是「数据库文件本身」这一层。

## 代价

- 换电脑、换系统账户、或系统钥匙串里的项被删掉时，旧的密文无法解密，需要重新填写密钥；
- 回退到这之前的版本时，旧版本读不懂密文，也需要重新填写；
- macOS 在 Electron 程序变化（例如升级 Electron）后，第一次访问钥匙串可能弹窗询问是否允许，选「始终允许」即可。

## 什么时候应该重新考虑

- 做云端多设备版时（服务器上的密钥保管方式不同，D-0013）；
- 其余随时可以。

## 修订记录

- 2026-10-27：初版让 `ai:ping` / `ai:check` 从环境变量取密钥，会让密钥以明文出现在终端历史或对话记录里；改为在 Electron 里运行检查，`ai:ping` 并入 `ai:check`。
