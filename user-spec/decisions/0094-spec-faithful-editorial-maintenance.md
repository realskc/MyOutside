# D-0094 统一 user spec 的记录规则，以忠实性和可读性共同检查

- 状态：有效
- 日期：2026-11-12
- 决策者：agent
- 服务于：[记录标准](../README.md#记录标准)（作者确认，2026-11-12）

## 背景

作者使用本机的 user-spec skill 改造 Braiser 后，发现总览几乎全是对话原句，阅读支离破碎。作者明确：内容来源于作者的意志，但记录由 agent 完成，无歧义的部分应以正常语言组织。

## 决策

- MyOutside 的主 README 集中定义记录标准，AGENTS.md、愿景记录规则和早期概念文档引用并统一口径；对平台文档中夹杂工作指令的部署段落作局部整理。
- 仓库外的通用 skill 同步修正正文、模板、完成标准和汇报要求：核验预期含义的来源与忠实性，并检查脱离会话后的可读性，不要求逐句对应原话。
- 忠实转述属于正文；「agent 注」只用于额外的解释、推断或联想。

## 修复的 bug

- 现象：Braiser 总览保留「先做到这个就行」等短答及其提问，一次性改造指令也与产品预期并列，读者需要拼接对话。
- 原因：skill 反复强调尽量使用原话、每句可定位和逐条汇报原话，只把整理描述为让句子通顺。
- 为什么原来的做法会出 bug：逐句照录最容易通过这些检查，却不能保证文档准确呈现当前预期；将内容来源与文字来源混为一谈，会抑制必要的编辑工作。
- 怎么验证修好了：检查规则中不再要求原话优先或逐句认可；对照「当前先支持这些能力即可」与永久性「产品只支持这些能力」，确认允许前者展开指代、禁止后者改变范围。检查改动后的主题段落能独立阅读，链接有效。此为规则与文档复核，尚未进行新 agent 的行为试验。

## 代价

需要 agent 判断含义是否保持一致；原句匹配不能代替这种判断。存在实质歧义且工作需要解决时，仍需与作者讨论。

## 什么时候应该重新考虑

出现新的实际案例，表明规则仍鼓励逐句摘录或容许 agent 借整理改变作者的预期时。
