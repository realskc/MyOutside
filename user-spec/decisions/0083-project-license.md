# D-0083 项目代码使用 Apache-2.0；第三方代码与模型权重单独处理

- 状态：有效
- 日期：2026-11-08
- 决策者：作者
- 服务于：
  - 作者预期：项目开源、允许别人使用和修改，并为将来可能的商业使用保留空间
  - 上游决策：无

## 背景

仓库此前没有 `LICENSE`，各 `package.json` 也没有 `license` 字段。公开可见不等于授权；其他人无法据此合法地复制、修改或再分发项目代码。

项目同时依赖第三方代码、模型权重和外部工具。代码许可证不会自动覆盖模型权重；例如 MuScriptor 的代码是 MIT，但权重是 CC BY-NC 4.0；BS-RoFormer SW 权重目前没有声明许可证。

## 决策

- MyOutside 自己的代码使用 **Apache-2.0**；
- 根目录提供 [LICENSE](../../LICENSE) 和 [NOTICE](../../NOTICE)；
- 第三方代码、模型权重和外部工具的许可证集中记录在 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)；
- 不把模型权重提交进仓库；模型由安装脚本或运行时从上游下载；
- Apache-2.0 只覆盖本项目自己拥有版权的代码，不改变任何第三方组件或模型权重的许可证；
- 公开分发或商业使用前，按 `THIRD_PARTY_NOTICES.md` 重新核对每个依赖和权重的许可证。

## 考虑过、没有采用

- **MIT**：更短更简单，但没有 Apache-2.0 的明确专利授权；作者选择 Apache-2.0。
- **GPL-3.0**：会要求分发衍生作品时提供源码；当前不采用，避免把整个应用强制 copyleft。
- **暂不添加许可证**：朋友和公开用户没有明确的使用授权，不适合当前目标。

## 代价

- 分发时需要保留 Apache-2.0 的 LICENSE / NOTICE，并标注修改过的文件；
- 仍需单独处理第三方代码、模型权重和 `ffmpeg` 等外部依赖；
- BS-RoFormer SW 权重许可证 unknown、MuScriptor 权重 CC BY-NC 4.0，这两个问题不会因为项目采用 Apache-2.0 而消失。

## 什么时候应该重新考虑

- 要采用 GPL/AGPL 代码并接受 copyleft；
- 要进行商业分发，而某个模型权重不允许商业使用；
- 要双许可证或更换项目许可证。
