# D-0017 开发时按子应用热重载（reloadApp）

- 状态：有效（尚未实现；推迟到做 builder 时一起做）
- 日期：2026-10-04
- 决策者：作者
- 服务于：
  - 作者预期：[platform.md「开发时的更新」](../platform.md)（不能靠整机重启）

## 决策

- 每个子应用的后端模块独立产出；
- 内核提供 `reloadApp`，在运行时只重载某一个子应用。

## 考虑过、没有采用

- 整机重启作为开发更新方案：会连带重启所有子应用、丢失会话。

## 相关文档

- `docs/architecture.md` §11

## 实现时机

- 2026-10-27 作者决定：推迟到做 builder 时再实现。届时「每个子应用的后端单独打包、单独加载」本来就要做（builder 新建、修改子应用，以及自动发现子应用都需要），热重载顺带完成；
- 在那之前，改了主进程里的代码（内核、平台 API、子应用后端）需要完全退出再启动；正常退出时进行中的生成会先保存已生成的部分（DIALOG-0017）；
- 评估时的判断：内核的「运行中替换子应用后端」与按子应用打包加载，云端多设备版（D-0013）可以复用，不会白做；暂缓是因为眼下收益小（省掉一次重启）、而处理进行中的调用与模块内状态的成本和风险不小。
