# D-0076 子应用可以在 MyOutside 启动时开始后台工作

- 状态：有效（未实现）
- 日期：2026-10-27
- 决策者：agent（作者暂时想不明白，先采纳 agent 的建议）
- 服务于：
  - 上游决策：[D-0062](0062-workflow-persistence-is-app-responsibility.md)（工作流的暂停与恢复由子应用自己解决）、[D-0063](0063-internal-apis-may-be-async-functions.md)（普通的异步函数）
  - 第一个使用者：[ZHEYE-0009](../../apps/zheye/user-spec/decisions/ZHEYE-0009-resume-on-startup.md)

## 决策

- 子应用的后端可以声明一个启动时运行的普通的异步函数；内核启动完成后调用它，调用者是这个子应用自己，没有推送通道；
- 它可以一直运行（例如逐篇生成文章），写数据照常只能通过本子应用的事务 API；
- 正常关闭 MyOutside 时，和进行中的调用一样收到取消信号，最多等 3 秒收尾（DIALOG-0017 的机制）；
- 恢复到哪里由子应用自己从数据里判断（D-0062），平台不记录进度。

## 理由

D-0062 让子应用自己负责暂停与恢复，但「恢复」需要一个不依赖前端的起点；否则重启后必须有人打开那个子应用，工作才会继续。这个机制是通用的，以后 builder 等也可能用到。

## 什么时候应该重新考虑

- 出现多个子应用同时在后台大量调用 AI、需要统一调度或限额时；
- 其余随时可以。
