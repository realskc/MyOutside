# D-0049 agent 能力分四部分：执行层承载循环，循环调用模型层与工具层

- 状态：有效
- 日期：2026-10-21
- 决策者：agent（用户认可了分层的大方向）
- 服务于：
  - 用户预期：[platform.md「平台 AI」](../platform.md)（agent 框架必须共享；硬约束在框架层面）
  - 上游决策：[D-0048](0048-self-built-agent-library.md)

## 决策

- **模型层**：`platform.ai.chat`，留在内核里（密钥在平台），负责用量计量；
- **循环库**：`packages/agent`，循环、事件、停止条件、出错处理、上下文控制、结构化输出；运行时无关；
- **工具层**：平台工具、应用工具（复用内核 API 函数）、跨应用工具；权限由内核按调用者检查；
- **执行层**：调用内运行（v1）与后台任务（以后），见 D-0052。

关系：执行层启动并承载循环；循环调用模型层与工具层（二者并列）；模型层与工具层的调用都经过内核。早期草稿把四者画成线性的 L0–L3，用户指出关系应是「执行层 → 循环 → 工具层 / 模型层」，据此修正。

## 理由

模型层必须在内核（密钥、计量）；循环逻辑与运行环境无关，适合做成纯库；权限必须落在内核才是硬约束；执行方式与内核事务模型深度相关，单独成层，可以分阶段实现。

## 什么时候应该重新考虑

随时可以，只要仍满足：agent 能力共享、密钥在平台、硬约束在框架 / 内核层。
