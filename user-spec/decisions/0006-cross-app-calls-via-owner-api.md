# D-0006 跨应用通道：只能调用对方的 API 函数，分事务内与事务外两种语义

- 状态：有效
- 日期：2026-09-30
- 决策者：讨论
- 服务于：
  - 作者预期：[platform.md「数据归属与子应用之间的连接」](../platform.md)（子应用之间不得混乱地相互调用；耦合要容易连接和剥离）
  - 作者预期：[principles.md「安装：Agent 适配」](../principles.md)（耦合点必须显式）

## 决策

- 每个子应用（以及平台）对外暴露 **API 函数**，这是跨应用的唯一通道；读别人的数据也只能调用对方提供的查询函数（没有通用的跨应用查询接口）；
- 两种调用语义：
  - **事务内**（`ctx.call`，在事务 API 里）：同步、纯数据，与本次写入同生共死——用于跨应用原子落账；
  - **事务外**（只读 API 里的 `ctx.call`、界面的 `outside.call`）：异步、无原子承诺；
- 契约（输入的 zod 校验、API 签名）统一放在 `packages/contracts`；
- 事件 / 消息总线暂缓，需要时再启用。

## 代价

- （已解决，2026-10-26）早期内核不区分调用者，「公开 API」的边界靠约定；现已由内核按调用者检查权限（D-0053、D-0070）。

## 什么时候应该重新考虑

- 出现大量「一对多通知」的需求，函数调用表达起来别扭时（考虑启用事件总线）。
