# D-0007 API 分事务 API 与只读 API 两类；事务 API 必须同步、纯数据

- 状态：有效
- 日期：2026-09-30
- 决策者：讨论
- 服务于：
  - 作者预期：[platform.md「数据一致性」](../platform.md)
  - 上游决策：[D-0004](0004-sqlite-single-writer-queue.md)

## 决策

- API 函数分两类：
  - **事务 API**（`tx`）：进入串行队列，在一个数据库事务内执行；必须**同步、纯数据**——只读写自己的数据，不做文件、网络等副作用；返回 Promise 会被内核拒绝；
  - **只读 API**（`read`）：直接执行，可以异步（例如调用平台 AI）；
- 只读 API 里只能调用只读 API，事务 API 里只能调用事务 API；
- 将来如需副作用，走提交后的钩子（post-commit）或补偿，不得混入事务。

## 代价

- 「先调 AI、再写库」这类操作必须拆成两步（见 D-0008）；
- agent 循环中途要写库时，现有的只读 API 无法直接完成——agent 框架设计时需要重新考虑这一点。

## 什么时候应该重新考虑

- 作者认为现行方案暂时可行，以后可能修改系统关于 API 与事务的设计（例如引入锁机制），目前没有研究新设计的必要（见 `platform.md`「数据一致性」）；
- agent 框架需要「异步流程中多次提交事务」的能力时（可能需要新的函数类别或任务机制）。
