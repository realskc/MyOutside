# D-0092 服务器数据的备份：每天打一个加密包传到 Cloudflare R2，按规则自动删、锁定期内谁也删不掉

- 状态：有效（程序已实现，R2 bucket、令牌和钥匙待作者在服务器终端配置）
- 日期：2026-11-11
- 决策者：讨论（作者选了 Cloudflare R2，要求 agent 讲清怎么操作、什么时候覆盖什么时候丢失、为什么能自动备份；具体做法由 agent 设计）
- 服务于：
  - 红线：[AGENTS.md「红线」](../../AGENTS.md)第 1 条（不能破坏作者的生活数据）——真实数据上服务器之前必须先有备份
  - 作者预期：[platform.md「分发与隔离」](../platform.md)（一定要防黑客）
  - 上游决策：[D-0091](0091-one-database-per-user.md)（每个用户一个数据库）

## 决策

**备份什么**：所有用户的数据库。不备份加密 API key 用的主密钥——服务器整个没了、从备份恢复时，用户重新填一次 API key 就行；这样备份泄露了也解不开 key。

**怎么自动备份**：服务器上有一个定时任务（systemd 的定时器，相当于闹钟），每天凌晨 4 点（香港时间）运行一次备份程序，每次部署前也运行一次：

1. 用 SQLite 自带的在线备份，给每个用户的库拍一份「快照」（服务在运行也能拍，拍出来是完整一致的）；
2. 检查快照完好（`PRAGMA integrity_check`），打成一个包、压缩、加密；
3. 上传到 R2 的桶 `myoutside-backup`：每天传到 `daily/`；星期天另传一份到 `weekly/`；每月 1 号另传一份到 `monthly/`；文件名带日期，不覆盖旧的；
4. 上传后再下载回来，核对和上传前一样。

**保留多久**（在 R2 上设规则，由 Cloudflare 执行，不靠服务器）：

| 文件夹 | 锁定（谁也删不掉） | 自动删除 |
|---|---|---|
| `daily/` | 7 天 | 8 天后 |
| `weekly/` | 35 天 | 36 天后 |
| `monthly/` | 180 天 | 181 天后 |

**加密**：用一把备份钥匙加密后再上传，Cloudflare 看不到内容。钥匙存两份：服务器上一份（只有备份程序能读），作者的密码管理器里一份——服务器整个没了，要靠作者那份解开备份。

**令牌**：服务器上放的 R2 令牌只能读写这一个桶里的文件，改不了锁定和删除规则。

**恢复演练**：每月自动把最新的备份下载、解密、打开检查一遍；失败要让作者知道。作者在网页上能看到上次成功备份的时间，超过一天没成功就标红。

**密钥不经过对话**：R2 令牌和备份钥匙由作者在自己的终端里 ssh 上服务器，运行 agent 给的命令，按提示粘贴（屏幕上不显示）；不贴进对话，不出现在 agent 的命令里（红线 3）。

## 能恢复到哪、什么时候会丢

- 能退回到：最近 7 天的任意一天；最近 5 周每周一份；最近 6 个月每月一份。更早的没有了。
- 两次备份之间的改动不在任何备份里：出事时最多丢不到一天（部署前也会备份）。

| 出了什么事 | 结果 |
|---|---|
| 服务器硬盘坏了 / 服务器被删了 | 从 R2 恢复，丢最近不到一天；用户重填 API key |
| 程序的 bug 改坏了数据，过几天才发现 | 退回到坏之前的那一份；那之后的正常改动也会丢，要么接受、要么手动挑回来 |
| 黑客进了服务器 | 能动服务器上的数据，也能拿到令牌；但删不掉还在锁定期的备份 |
| 我们自己误删了备份 | 锁定期内删不掉 |
| Cloudflare 账号出问题 | 服务器上的数据还在，重新建备份 |
| 服务器和 R2 同时没了 | 全丢（两家公司，可能性很小） |
| 两份备份钥匙都丢了 | 备份解不开，等于没有 |

## 考虑过、没有采用

- **UCloud 的硬盘快照**：和服务器在同一家；UCloud 账号出了问题会一起没。
- **拉回作者的 Mac**：公司电脑，有数据防泄漏软件；关机时备份不了。
- **restic 这类增量备份工具**：只传变化的部分、省空间；但它要删旧数据块，和「锁定期内谁也删不掉」不好配合。现在数据很小（作者的库 12 MB，压缩后更小，所有备份加起来几十 MB，远低于免费的 10 GB），每天整包更简单。用户多、数据大了再换。

## 代价

- 作者要在 Cloudflare 后台操作一次（开通 R2、建桶、设规则、建令牌），要保管一把备份钥匙。
- 每天整包，数据大了会占空间。

## 什么时候应该重新考虑

- 备份总量接近免费额度时（换增量备份）；
- 需要比「一天」更细的恢复点时（提高频率，或者连续备份）。

## 怎么验证

- 每月的恢复演练；
- 第一次上线前，手动做一次「从 R2 恢复到一台全新的库」的完整演练。
