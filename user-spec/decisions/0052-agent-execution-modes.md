# D-0052 agent 的两种运行模式：调用内运行先行，后台任务后置

- 日期：2026-10-21

  - 作者预期：[platform.md「数据一致性」](../platform.md)
  - 作者预期：[product.md「用户与阶段」](../product.md)（先推进实用的功能）
  - 上游决策：[D-0007](0007-sync-pure-tx-functions.md)、[D-0049](0049-agent-layering.md)

## 决策

- **调用内运行**（v1）：循环跑在只读 API 里，生命周期等于这次调用；工具只读；结果由事务 API 落库。对话搜索用这种模式，内核的事务模型不用改。
- **后台任务**（以后，哲野 / builder）：内核管理的异步任务；每步写日志、可重放续跑；中途写库时「数据写入 + 这一步的日志」在同一事务里提交（恰好一次）；内核记录变更前的数据以支持撤销整次任务；可暂停等待用户批准。
- 事务 API 仍然同步、纯数据：后台任务是新增的异步编排者，不改变 D-0007。

## 理由

对话搜索的工具都是只读的，不需要中途写库，先用最简单的模式落地；后台任务涉及日志、重放、变更日志，等哲野真正需要时再设计。所有数据写入都经内核、写进同一个 SQLite（D-0004），使「恰好一次」与「撤销」对数据部分可以真正实现——这是通用 agent 框架做不到的。

## 什么时候应该重新考虑

- 开始实现哲野或 builder 时（细化后台任务）。
