# D-0053 调用权限：应用声明自己会调用哪些函数，内核强制检查

- 状态：有效（未实现）
- 日期：2026-10-21
- 决策者：讨论（作者选择了方案 A）
- 服务于：
  - 作者预期：[principles.md「统一的内核让 agent 更安全」](../principles.md)（内核管控 agent 能使用的工具）
  - 作者预期：[principles.md「约束：软约束与硬约束都要」](../principles.md)
  - 作者预期：[platform.md「数据归属与子应用之间的连接」](../platform.md)（子应用之间不得混乱地相互调用）

## 决策

- 内核识别每次调用的**调用者**（后端发起：`ctx.appId`；前端发起：IPC 的 `senderFrame` 所属子应用；外壳 = 平台自身）；
- 每个子应用在**清单**（manifest，D-0056）的 `uses` 里**声明自己会调用哪些其他应用 / 平台的函数**；内核拒绝未声明的跨应用调用（调用自己的函数不受限）；
- **平台 API 也要声明**：子应用调用平台 API 同样需要写进 `uses`（例如对话声明 `platform.ai.chat`）——看清单就知道哪些子应用会用到 AI、搜索这类花钱的能力，也为将来按子应用管控 token 提供依据；
- **平台 API 不分公开 / 内部，而是逐个规定访问规则**：默认对子应用开放，少数只给外壳（例如修改平台设置）；
- agent 的工具最终都经 `ctx.call`，因此同样受这道检查——即使工具清单写错或模型被诱导，也越不过；
- 平台设置：子应用可以读取、不能修改，只有外壳可以修改；凭据（如 API Key）任何子应用都不能读取，外壳也读不到值、只能知道「是否已设置」（作者确认）（顺带解决 D-0019「子应用能读到密钥」的问题）；
- 开发阶段 agent 可以随意修改声明；builder 修改声明的权限另行讨论（D-0056）。

## 考虑过、没有采用

- 只管写操作（只读 API 谁都能调）：读操作完全不设防，例如任何应用都能读对话记录。
- 现在不做检查、以后再补：硬约束暂时为零。

## 代价

- 每新增一处跨应用耦合，要多写一行声明。

## 什么时候应该重新考虑

- 声明的粒度不合适时（太粗或太细），可以调整粒度，但不应退回到「不检查」。
