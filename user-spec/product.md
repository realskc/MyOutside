# 产品：MyOutside（地球online）

## 名字与寓意

良好的人生，应该把生活看作一场游戏——**地球online**（Outside）。

- 这是一个**开放世界游戏，没有主线**。所有的目标，都是人给自己定的任务。
- 无聊地度过生活的人像 NPC；真正享受生活、挑战世界的人，才是**玩家**。
- 我们睁开眼睛就是世界——就像这个游戏只有地图，却没有属性、商店、图鉴这些面板。这是不够好的。

**MyOutside 要成为地球online 里每一位玩家的个人游戏面板，为这场游戏（也就是人生和生活）提供支撑。**

英文名 MyOutside，中文名地球online。

## 产品命题

Vibe coding 让"做软件"的成本降到了前所未有的低点，"自己做应用"不再是瓶颈。

MyOutside 是一套特殊的应用：

- **每个人都可以用**；
- 但**每个人的应用都不一样**。

它的核心是**子应用**：用户在 MyOutside 里装载、组合、改造自己的子应用集合，得到一套只属于自己的软件。

两大核心能力：

1. **自由定制**：组成哪些应用、每个应用长什么样、怎么工作，都由用户自己决定。
2. **强耦合的复合能力**：子应用之间相互耦合，在「生活工作流」层面产生远强于单个应用的能力与便利。例：对话里随手记下的生词，自动进入学英语应用的记忆计划。

## 技术层面的预期：新的 vibe coding 范式

MyOutside 的特性——解耦合（清晰的边界）、user spec 等——要成为**新的 vibe coding 范式**。

- 作者的朋友、乃至外来的用户，都通过 vibe coding（也就是将来的 builder）来编写自己的应用；
- 用 builder 编写应用要有很好的使用体验：**不用关心技术细节，又能又快又好地实现想法**。

## 双重使命

MyOutside 同时承担两个使命：

1. **服务作者本人的生活**——这是很重要的任务，不只是产品的副产品；
2. **实现产品命题**——让每个人都能拥有自己的那一套应用。

两者的关系：

- **做细节开发和实现时，以服务个人生活为第一目标**，同时**不要堵死产品化的路**；
- 如果在**需求层次**上发现两者冲突，不要自行取舍：把觉得冲突的原因告诉作者，由作者决定。

## 服务个人生活：三个方向

1. **用专门的应用解决特定需求**：生活中一些特定的需求，通过自己 vibe coding 专门的应用来解决。例：学知识、读论文——因此有了哲野（见 `apps/zheye.md`）。
2. **借助 LLM 的高智力，提供更高层次的生活帮助**：例如智能任务列表——LLM 帮我拆解任务、把大任务化小、给我打气，帮助我更好地实现目标、管理生活。（后话）
3. **记录**：让工作和生活能好好地保存下来，为人类生活提供**连续性**支撑。

## 用户与阶段

- **阶段 0（现在）**：只有作者一个人使用。**现阶段先推进实用的功能和 demo**；长期才需要考虑的事（例如数据保存多年、界面层面的游戏面板比喻），留到以后。
- **阶段 1**：如果好用，分发给身边的朋友，每个人有自己的应用组合。朋友不会写代码，顶多会使用 agent——他们通过 builder 编写应用（见上文「新的 vibe coding 范式」）。
- **阶段 2**：上线部分平台能力：
  - 提供先验偏置、框架（脚手架、模板、范式），降低新子应用的开发成本；
  - 让"安装别人写的子应用"变得容易。

## 平台

- **Windows 与 macOS 是真实在用的平台**（作者两台电脑都在用）；**Linux** 暂时没用，但非常常见，也要支持。
- **手机**是关键需求：将来要在手机上使用，个人数据在电脑与手机之间共用（详见 `platform.md`）。
