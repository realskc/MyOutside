# 子应用的组成

「前端」「后端」出现时，**特指子应用的组成部分**。

## 后端

- 定义：子应用中**拥有数据**、并负责**不管谁来调用都必须成立的规则**的部分；对外提供功能，没有前端也能被调用。
- 例子：学英语的后端拥有卡片数据；复习调度算法（按了「不错」之后下次什么时候复习）在后端——不管是作者在复习页按按钮，还是将来某个 agent 帮忙提交复习结果，都按同一套算法算。
- 例子：将来对话应用可以直接调用学英语的后端加词，不需要打开学英语的前端。

## 前端

- 定义：子应用中负责**显示与交互流程**的部分；只通过自己的后端访问自己的数据。
- 例子：学英语的复习页——先取一批待复习的卡片、显示正面、点「显示答案」后显示释义与下次间隔、点「不错」后提交结果、进入下一张；这套流程与显示在前端，计算间隔、保存结果在后端。
- 前端与后端不在同一个地方运行（前端在窗口里，后端在 Electron 主进程里），前端调用后端只能经过内核。

## 清单（manifest）

- 定义：描述子应用、并声明其权限的那份数据。
- 例子：对话的清单写着：我叫「对话」，我会调用平台 AI 和搜索。
- 将来在 builder 上有独立的权限限制，不能随着改代码一起被随意修改。
- 不是：清单不包含 API 与迁移——那些是后端代码。

## API

- 定义：经内核调用的、有名字和参数校验的功能入口。子应用的后端提供 API；平台也提供 API。
- 按可见性分两种：
  - **公开 API**：其他子应用可以调用（还需在自己的清单里声明）；跨子应用的语境下，说「API」或「公开 API」都可以。例：`vocab.addCard`（加卡片）。
  - **内部 API**：只有本子应用自己能调用，可以随时修改。例：只为学英语复习页准备数据的函数。
- 按执行方式分两种（与公开 / 内部互相独立，四种组合都可能）：
  - **事务 API**：在事务里执行的 API。同步执行——几毫秒内做完，中间不等任何外部的东西；可以读也可以写数据；要么全部生效、要么全部不生效；执行期间不受其他写入干扰。在事务 API 里调用其他子应用的事务 API，属于同一个事务（跨子应用的原子写入）。例：`vocab.addCard`（加卡片）、`dialog.appendMessage`（保存消息）。
  - **只读 API**：不在事务里执行的 API。**不能修改数据**，但可以异步——中间可以等外部的东西（等 AI 回复、等搜索结果）。例：`vocab.getDue`（取待复习卡片）、`vocab.resolveCard`（问 AI 新卡片是否与已有卡片同义）。
  - **写数据只能通过事务 API**。
  - 公开 API 只能是只读 API 或事务 API；**内部 API 还可以是普通的异步函数**：可以等外部，需要写数据时调用本子应用的事务 API（每次是一个独立的短事务），整体不保证原子。例：对话的 `dialog.send`——先调用事务 API 保存用户的消息，再等模型生成回复（中间可能搜索几次），最后调用事务 API 保存回复。见 [D-0063](../decisions/0063-internal-apis-may-be-async-functions.md)。
- 不是：后端代码里普通的函数——只有经内核调用的才是 API。
- 「事务」本身暂不作为概念：抽象出来势必涉及错误恢复、连环事务等更多设计考量，现阶段先使用现状，等将来做大了再思考这部分的系统设计。

## 平台 API

- 定义：**平台提供的 API**，不属于任何子应用。
- 例子：`platform.ai.chat`（平台 AI）、`platform.settings.get`（读平台设置）、将来的 `platform.web.search`（搜索）。
- 与子应用的 API 一样经内核调用、有名字与参数校验；区别只在由谁提供。
- 访问规则（哪些平台 API 子应用能调、是否需要在清单里声明）属于现行决策，见 [D-0053](../decisions/0053-kernel-enforced-call-permissions.md)。
