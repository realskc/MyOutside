# 主体

主体分两个层面，**完全是两个层面的东西**：

- **社会主体**：产品层面——谁掌控产品的设计与定位、谁使用产品、谁开发和维护子应用；
- **技术主体**：系统权限层面——在系统里以什么权限行动。

两个层面之间没有对应关系；唯一的联系是同一个人可以同时具有多重身份（例如作者同时也是开发者、也是用户）。

## 社会主体

### 作者

- 定义：掌控整个 MyOutside 的设计与定位的人，即项目作者本人。
- **MyOutside 的 user spec 就是作者的意志。**
- 凡是指项目作者本人的地方，都说「作者」，不说「用户」——包括与 agent 协作的场景（agent 领域习惯把和 agent 对话的人叫「用户」，在本项目里这个人是作者）。

### 用户

- 定义：使用 MyOutside 产品的人。
- 例子：作者日常用学英语背单词、用对话聊天时，是用户；阶段 1 分发给朋友后，朋友是用户。

### 子应用作者

- 定义：开发和维护某个子应用的人。
- 将来每个子应用有自己的 user spec，**子应用的 user spec 是子应用作者的意志**。
- 例子：学英语、对话、哲野的子应用作者目前都是作者本人；阶段 2 安装别人写的子应用时，写它的那个人是该子应用的子应用作者。

## 技术主体

目前只有以下三类。

### 开发者

- 定义：直接开发 MyOutside 的人或 agent（内核、平台、子应用的代码都在其范围内）。
- 包括：作者、编码 agent、将来可能加入的开发者。

### builder

- 定义：builder 以及使用 builder 的用户。
- 权限：留到设计 builder 时讨论（见 `../future/builder.md`）。

### 子应用

- 定义：子应用以及使用子应用的用户。
- 权限：只能访问自己的数据；跨应用调用需要在清单里声明（见 [D-0053](../decisions/0053-kernel-enforced-call-permissions.md)）。
- 子应用里运行的 agent 目前和子应用的常规逻辑属于同一个技术主体；将来是否把二者分化为两类权限主体，再说。
