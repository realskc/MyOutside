# NETEASE-0001 网易云下载：读官方客户端的登录状态，搜歌、按账号允许的最高音质下载

- 状态：有效（「每次下载记一条记录」被 [NETEASE-0002](NETEASE-0002-download-rate-limit.md) 取代：只记真正下载了的；下载加了排队、间隔和每天上限）
- 日期：2026-11-11
- 决策者：agent（定位、范围、下载位置、命名由作者定，见应用 spec）
- 服务于：
  - 作者预期：[`../README.md`](../README.md)：只做搜索和下载；只给作者自己用；不负责登录、凭据从本地抓；付费歌和高音质都可以下；默认下载到网易云音乐的文件夹，可以改；和官方客户端一样命名并存歌词；不自动导入纯蓝，最多开放下载文件夹
  - 红线：[AGENTS.md「红线」](../../../../AGENTS.md)第 1–3 条（不破坏作者的数据、开发不打扰作者、密钥不能泄露）

## 决策

### 登录状态

- 读官方 macOS 客户端的 Cookie 文件 `~/Library/HTTPStorages/com.netease.163music.binarycookies`（Apple 二进制 Cookie 格式），取 `.music.163.com` 域、路径 `/` 的 `MUSIC_U`；只认唯一的一个。也找 App Store 版可能的位置 `~/Library/Containers/com.netease.163music/Data/Library/HTTPStorages/…`（推断，没验证）。
- **每次请求都重新读**：作者在官方客户端里换账号、重新登录，马上生效。
- 凭据只在后端内存里用：只放进发给 `interface.music.163.com` 的 Cookie；下载音频的 CDN 请求不带它；报错信息里不带它，也不带签名的下载地址。

### 接口

只用四个：`/api/cloudsearch/pc`（搜索）、`/api/v3/song/detail`（歌曲详情和本账号的权限）、`/api/song/enhance/download/url/v1`（下载地址）、`/api/song/lyric`（歌词）。都是表单 POST，Cookie 是 `MUSIC_U=…; os=osx`，User-Agent 用官方 macOS 客户端的。

2026-11-11 在作者账号上实测：

- **`os=osx` 要带**：不带时，《白石溪》无损拿到的 CDN 地址被拒（403），带了就能下；标准、320k 两种不带也行。
- User-Agent：普通的 UA 下标准音质也行；没测高音质，保险起见照官方客户端。
- 作者是会员：免费歌（fee 0）最高能下无损，fee 8 的歌最高 320k；**付费歌下下来也是普通的 MP3**（《汉江恋》320k，ID3 开头），无损是普通 FLAC；大小、MD5 都和接口给的一致。没遇到加密的 `.ncm`。
- 歌词接口给的是标准 LRC；和官方客户端存的 `.lrc` 比，只有开头作词、作曲两行的写法不同。
- 歌词请求偶尔会失败一次。

### 下载

- 档位：不指定就用详情里 `privilege.dlLevel`（这个账号能下的最高档位）；指定的档位超过它就拒绝。
- 位置：默认 `~/Music/网易云音乐`（这台 Mac 上官方客户端的下载文件夹；它的偏好设置里没找到下载位置的配置项）；设置里可以改，记在 `setting` 表里。
- 命名：`歌手1,歌手2 - 歌名.扩展名`，名字里的空格换成不换行空格（U+00A0）、`/` 换成全角 `／`（本机官方客户端的文件就是这样）；其余 Windows 不允许的字符也换成全角。
- **不覆盖**：文件夹里已有同名文件（例如官方客户端下过）就不下载；歌词文件也一样。
- 先写 `<文件>.part`，大小和 MD5 都对了才改名；出错或取消时删掉。同一首歌同时下两次，第二次报「正在下载」。
- 歌词：重试一次；还失败就不存、照样下完，进度消息里说明；再下一次同一首歌会补上。
- 每次下载记一条 `download` 记录（歌、档位、文件、大小、时间），界面显示「最近下载」。

### 给其他子应用

- 公开 API 只有 `netease.listDownloadedFiles`：下载文件夹里的音频文件和同名歌词（作者：最多向纯蓝开放下载的音乐文件夹）。
- 下载不公开：它是普通的异步函数，而公开 API 只能是只读或事务（D-0063）。纯蓝真要下载时，要先在平台层讨论怎么开放。
- 不自动导入纯蓝。

### 开发和检查不碰作者的账号

- 单测用假的 Cookie 文件和假的网络请求。
- 冒烟检查不给 Cookie 文件的位置、下载文件夹放在临时数据里，不发任何网络请求；检查界面显示「未登录」、搜索不可点。
- 用真实账号的检查只在开发时手动做，下载到临时目录，不写作者的音乐文件夹。

### 外壳

- 新增 `host:pickFolder`（选文件夹）和 `host:revealPath`（在访达里显示文件或打开文件夹），子应用页面才能调用。

## 考虑过、没有采用

- **在子应用里登录**：作者要求不负责登录；扫码登录还要处理风控和刷新。
- **用 Python 脚本**：几个 HTTP 请求和一个二进制格式，TypeScript 后端就能做，不用额外的运行环境。
- **下载到应用自己的数据目录**：作者要默认放在网易云音乐的文件夹，和官方客户端下的歌放在一起。

## 代价

- 用的是非官方接口，网易云改了就要跟着改；请求太频繁，账号可能被风控（只在作者操作时请求，没有批量）。
- 只支持 macOS；Windows 上怎么取登录状态还没研究。
- 代码在公开仓库里（作者决定：现阶段只给自己用，分发时再讨论）。

## 什么时候应该重新考虑

- 网易云的接口、Cookie 位置或格式变了；
- 要支持 Windows；
- 纯蓝要直接下载（公开下载能力）；
- 要分发给别人。

## 怎么验证

- 单测（`apps/netease/test/netease.test.ts`）：读 binarycookies；官方式命名；没登录时的状态；搜索请求带 `MUSIC_U` 和 `os=osx`、报错不带凭据；下载按最高档位、存歌词、记录、CDN 不带 Cookie；已有文件不重复下载；档位超权限拒绝；MD5 不对不留文件；歌词失败重试和补齐；别的子应用只能调 `listDownloadedFiles`。
- 冒烟 `netease`：未登录显示、搜索不可点、下载文件夹在临时数据里、外壳的两个新函数在。
- 2026-11-11 用作者账号手动检查（下载到临时目录）：搜《阳山绝》，下载 320k MP3（11,089,546 字节）和歌词，再下一次报「文件夹里已经有了」，`listDownloadedFiles` 列出它和歌词。
