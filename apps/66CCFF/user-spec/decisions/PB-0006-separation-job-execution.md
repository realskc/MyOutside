# PB-0006 分离任务：内部异步 API + runId 事件 / 取消

- 状态：有效
- 日期：2026-11-04
- 决策者：agent
- 服务于：
  - 作者预期：[`../README.md`](../README.md)「核心流程与预期」可见进度、失败原因
  - 上游决策：D-0063、D-0051

## 背景

分离一首歌通常需要几十秒到几分钟，不能在事务 API 里做；同时界面需要实时进度并可以取消。内核已经提供普通异步函数（`defineAsync`）、调用级推送事件与取消信号（`ctx.emit` / `ctx.signal`）。

## 决策

- `66CCFF.startSeparation` 定义为内部异步 API：创建任务记录 → 启动 Demucs 子进程 → 解析 stderr 进度 → 用事件推送给界面 → 完成时用事务 API 写六轨记录；
- 界面用 `runId` 订阅事件，并用 `bridge.cancel(runId)` 取消（取消时终止子进程、任务标记为 canceled）；
- 同一曲目同一时间只允许一个分离任务。

## 代价

- 页面刷新 / 关闭后，正在进行的任务仍由主进程继续执行，但界面丢失事件；重新打开后靠查询任务状态恢复显示。
- 尚未接入将来的平台后台任务（D-0052），任务日志只保留最后一段消息。
