# 66CCFF-0010 MIDI 卷帘：先做只读对比查看器

- 状态：有效
- 日期：2026-11-08
- 决策者：作者（提出需求；具体界面由 agent 设计）
- 服务于：
  - 作者预期：[`../README.md`](../README.md)「界面」增加 MIDI 卷帘
  - 上游决策：[66CCFF-0007](66CCFF-0007-basic-pitch-midi.md)（MIDI 转写）

## 背景

作者需要比较不同 MIDI 转写结果（例如 MuScriptor 与 Transkun）的音符差异，单靠耳朵不够，需要钢琴卷帘。第一版暂不要求编辑功能。

## 决策

- 在纯蓝界面内增加 **MIDI 卷帘**，从曲目详情打开；
- 第一版是**只读对比查看器**：
  - 一次可以选择一个或多个 MIDI 文件；
  - 多个文件/轨道用不同颜色叠加显示；
  - 支持横向缩放、拖动、滚轮缩放、适应全曲；
  - 鼠标悬停显示文件、轨道、音名、开始时间、时长、力度；
  - 轨道可以单独开关；
  - 不做编辑、保存、播放和转写集成。
- 渲染使用 Canvas 2D；MIDI 解析放在后端（`@tonejs/midi`），前端只接收秒制音符 JSON；
- 文件通过系统文件选择器选择，路径由宿主提供；MIDI 不复制进应用目录，也不写入数据库；
- 后续再考虑：播放头与 stem 音频同步、MIDI 播放、循环、转写结果持久化和钢琴卷帘编辑。

## 考虑过、没有采用

- **DOM 音符元素**：几千个音符时性能和维护成本都更差；Canvas 更适合时间轴绘制。
- **引入现成 DAW / 钢琴卷帘组件**：依赖和交互范围过大；第一版只需要看差异。
- **直接把 MIDI 解析放在前端**：零构建界面需要额外打包 parser；后端解析后返回 JSON 更简单。
- **第一版就做播放/编辑**：目前目标是 A/B 对比，不是完整 MIDI 工作站。

## 代价

- 新增 `@tonejs/midi` 依赖；
- 文件选择器只在 Electron 宿主可用，LAN / 浏览器版暂不支持；
- MIDI 不持久化，关闭界面后重新选择；
- 还没有播放和编辑，不能替代 DAW。

## 什么时候应该重新考虑

- 需要长时间保存 MIDI 结果或从应用内直接运行转写；
- 需要播放、循环或与音频精确同步；
- 需要编辑、量化、导出或音符修正；
- 需要 LAN / 浏览器版也支持文件选择。
