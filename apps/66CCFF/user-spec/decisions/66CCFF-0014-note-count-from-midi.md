# 66CCFF-0014 转写结果的音符数从写好的 MIDI 里数，不用 MuScriptor 的「音符开始」计数

- 状态：有效
- 日期：2026-11-09
- 决策者：agent
- 取代：[66CCFF-0012](66CCFF-0012-muscriptor-in-app-transcription.md) 中「音符数由包装脚本报告」的部分
- 服务于：
  - 作者预期：[`../README.md`](../README.md)「界面」钢琴卷帘要能方便地查看
  - 上游决策：[66CCFF-0012](66CCFF-0012-muscriptor-in-app-transcription.md)（转 MIDI 接进纯蓝）

## 决策

- 转写完成后，纯蓝解析刚写好的 MIDI（和卷帘用的同一个解析函数），把各轨音符数加起来存进记录；包装脚本不再报音符数。

## 修复的 bug

- **现象**（agent 检查《白石溪》的转写结果时发现，2026-11-09）：纯蓝记录伴奏转钢琴有 13,625 个音符，MIDI 文件里实际只有 4,317 个；人声旋律记录 652 个，实际 538 个。界面显示的数和卷帘里看到的对不上。
- **原因**：包装脚本数的是 MuScriptor 输出的「音符开始」事件。MuScriptor 按 5 秒一块解码，每块开头会把上一块还在响的音符重新声明一次；写 MIDI 时这些会合并成一个音符，但事件里各算一次。长音（铺底、弦乐）越多，多算得越厉害。
- **为什么原来的做法会出 bug（重构时不能再用）**：不能拿转写模型的事件流来统计音符；凡是给作者看的音符数，都以最终写出的 MIDI 为准。
- **怎么验证修好了**：`apps/66CCFF/test/x66ccff.test.ts`「转 MIDI：两条 stem 先混成一条……」里，假的引擎像真的 MuScriptor 一样多报音符数（报 99 个），MIDI 里只有 2 个；测试要求记录和返回值都是 2。
- 这台 Mac 上已有的两条记录做了一次性更正：652 → 538，13,625 → 4,317。
