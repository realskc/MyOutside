# 66CCFF-0015 钢琴卷帘放进曲目页，和分轨播放器共用一条时间线；加竖着的沉浸模式

- 状态：有效
- 日期：2026-11-10
- 决策者：agent（作者提出预期；界面与实现由 agent 设计）
- 服务于：
  - 作者预期：[`../README.md`](../README.md)「界面」里钢琴卷帘的几条（当谱看、两种模式、GarageBand 那些好处、竖着的沉浸式播放）
  - 上游决策：[66CCFF-0010](66CCFF-0010-midi-roll-viewer.md)（第一版卷帘，本决策取代其中的大部分）、[66CCFF-0011](66CCFF-0011-mute-with-gain-nodes.md)（混音用音量节点）、[66CCFF-0012](66CCFF-0012-muscriptor-in-app-transcription.md)（转写结果存进曲目）

## 背景

第一版卷帘（66CCFF-0010）是一个弹窗：要手动选 MIDI 文件，有自己的三角波播放和播放头，和分轨播放器互不相干。作者觉得 UI 和交互「实在太差」。之后作者试了 GarageBand、Signal、Midiano，说清楚了想要什么（见应用 spec「界面」）。转 MIDI 的方案还没定，作者要先有一个好用的卷帘，才能判断转出来的 MIDI 好不好。

## 决策

### 位置和时间线

- 卷帘是曲目页里**播放器下面的一块面板**，不再是弹窗；有分轨（也就是有播放器）时出现，高度可以拖右下角调整。
- 卷帘**没有自己的播放器**：时间、播放 / 暂停、慢放、跳转、AB 循环都以分轨播放器为准。卷帘里点或拖标尺 = 让播放器跳过去；卷帘工具栏上的播放键和空格键也走播放器。

### 显示什么

- 自动读这首曲目**所有成功的转写结果**。第一次打开只显示最新的一个，之后新转出来的直接显示。转 MIDI 列表里，每条结果有「在卷帘中显示 / 从卷帘隐藏」。
- 还可以「添加 MIDI 文件」（系统文件选择器）。手动添加的不存，换曲目就清掉，可以单独移除。
- 每条轨一种颜色，**叠在一起**显示。图例里每条轨一个按钮，点一下显示 / 隐藏。

### 横向卷帘

- 左边一排琴键，正在响的键用那条轨的颜色点亮；时间从左往右，有红色播放头。
- 拍线、小节线、标尺上的小节号：来自 MIDI 的速度表和拍号（MuScriptor 写进了检测到的速度），没有拍号按 4/4。由后端算好，作为 `grid { beats, bars }` 返回（最多 20000 拍）。小节号太密时隔几个标一个，没有节拍信息时标尺标时间。
- 块够大时（行高 ≥ 11px、块宽 ≥ 26px）块上写音名。悬停显示音名、开始时间、时长、力度、来源；点音符或琴键试听一下。
- 移动和缩放，左右上下都有（作者：上下很关键）：
  - 滚动 / 拖动：上下左右移动；
  - 双指捏合或 ⌘ / Ctrl + 滚动：时间缩放，以鼠标位置为中心；在左边琴键上捏合则是音高缩放；
  - ⌥ / Alt + 滚动：音高缩放；
  - 工具栏「时间 − +」「音高 − +」：时间缩放以播放头为中心（播放头不在画面里就以画面中间为中心），音高缩放以画面中间为中心；
  - 「适应」：竖向放下**大部分音符**（去掉最低、最高各 1% 的零星音；行高至少 8px），并回到播放头。
- 「跟随」开着时，播放头快出画面就翻一页。播放中手动左右移动会关掉跟随，再点一下打开。

### 沉浸模式（竖着）

- 铺满整个窗口，深色背景。音符往下落到底下的琴键上，正在响的键用轨的颜色点亮；有小节横线和小节号，按轨上色；块够大时写音名（不带八度）。不显示图例、多轨控件和缩放以外的按钮。
- 琴键范围按显示中的所有音符取整到八度，至少两个八度，最多 88 键。
- 顶上一条细进度条，点击或拖动可以跳转；滚动 = 前后移动时间；⌘ / Ctrl + 滚动或「− +」调下落速度；「适应」恢复琴键范围和下落速度；Esc 或「退出沉浸」回到卷帘。

### 声音

- 一个简单的合成音：三角波加高八度正弦，像钢琴那样起音快、按音高衰减。它不是真实钢琴采样。
- 合成器接在混音的同一个 `AudioContext` 上。卷帘里有显示中的轨时，混音里多一轨「MIDI」，和分轨一样可以静音、独奏、调音量（沿用 66CCFF-0011 的音量节点）。
- 发声的是显示中、有音高的轨；鼓轨（MIDI 第 10 通道，后端返回 `percussion`）只显示不发声。
- 排音方式（`ui/midi-synth.js`）：
  - 每 25 毫秒按**播放器的当前时间**往后排 0.3 秒；窗口隐藏时定时器大约一秒才跑一次，改为 1.6 秒；
  - 往回跳（包括 AB 循环跳回 A 点）、往前跳超过 0.5 秒、换了速度时，停掉排好的音，从当前时间重新排；
  - 重新排时往回多算 30 毫秒。从某个音的开头开始播时（小节线、A 点），第一次排音前播放器可能已经走过了一点点，不多算这个音就丢了；
  - 刚开始播或刚跳转时，播放器的时间会停几十毫秒才走。要等它真的走起来再排，照着停住的时间排，第一个音会提前（实测提前约 50 毫秒）；
  - 已经过去的音不补，否则窗口隐藏后等得久，会一下子全响。

### 删除

- 删掉旧弹窗（`#midi-modal`）、它的三角波播放、独立播放头和相关文案、样式。

### 66CCFF-0010 里仍然有效的

- 渲染用 Canvas 2D；MIDI 由后端用 `@tonejs/midi` 解析，前端只拿秒制音符 JSON；
- 手动添加的 MIDI 用宿主的系统文件选择器，不复制进应用目录、不写数据库；
- 不编辑。

## 考虑过、没有采用

- **保留弹窗，卷帘自己播放**：没法和分轨对照。作者要拖动播放位置、跟着分轨看，时间线只能有一条。
- **每条轨一条泳道（GarageBand 那样一次只放大一条）**：作者希望多轨叠在一起比较，所以用叠加 + 颜色 + 开关。
- **真实钢琴采样（SoundFont 一类）**：要下载或打包几 MB 到几十 MB 的采样，选哪套也需要作者听过再定；先用合成音，作者听了再说。
- **用 Tone.js 之类的调度库**：要引依赖，而且仍然要和 `<audio>` 对时间；直接按播放器的时间排更简单。
- **「适应」时放下所有音符**：MuScriptor 的结果里有零星的极高 / 极低音，会把行高压到最小（白石溪上就是这样），所以用 1%–99%。零星的音滚动过去还能看到。
- **WebGL**：Canvas 2D 画白石溪的两个转写结果（共 4,855 个音符）两种模式都是 120fps，暂时不需要。

## 代价

- 合成音不是真实钢琴；
- MIDI 和分轨的同步靠按播放器时间排音：第一个音最多晚一个排音周期（约 25 毫秒）。`<audio>` 经 Web Audio 出声的固有延迟没有校准，以作者的听感为准；
- 小节线用第一条显示中的轨的速度表。不同 stem 转出来的速度不一样时（白石溪：人声约 99 BPM，伴奏约 86 BPM），小节线只对得上其中一个（66CCFF-0017 起，新转的结果都在整首歌上检测节拍）；
- 手动添加的 MIDI 换曲目就没了；
- 沉浸模式的琴键范围算上了零星音，音域宽时键会比较窄。

## 什么时候应该重新考虑

- 作者觉得声音不好听，或者想要真实钢琴音色；
- 作者听出 MIDI 和分轨对不齐；
- 要编辑音符、量化或导出；
- 要在横向卷帘里显示歌词等其他东西（应用 spec 提到过）；
- 小节线要按整首歌检测一次节拍，而不是用某条轨的 MIDI 速度；
- 音符多到 Canvas 2D 画不动。

## 怎么验证

- 冒烟 `66CCFF roll`：给冒烟曲目写一个转写结果，卷帘读出来，混音里出现「MIDI」，能进入并用 Esc 退出沉浸模式；截图 `myoutside-66CCFF-roll.png`、`myoutside-66CCFF-fall.png`（系统临时目录）。
- 冒烟 `66CCFF roll synth`：把窗口静音（不出声），50% 速度从第 2 秒开始播约 2.6 秒。冒烟 MIDI 在第 2、3 秒各有一个三和弦：应排出 12 个振荡器，两组开始时间相差 2 秒（误差 < 0.06 秒），暂停后不再排新的音。
- 单测「readMidi 按速度表算出拍和小节线」。
- 2026-11-10 一次性预览：白石溪的两个转写结果（人声 538 个音符、伴奏 4,317 个）在隐藏窗口里画两种模式，截图检查。
