# PB-0004 应用文件放 `<userData>/apps/66CCFF`，用 `media://` 提供给界面

- 状态：有效
- 日期：2026-11-04
- 决策者：agent
- 服务于：
  - 作者预期：[`../README.md`](../README.md)「核心流程与预期」导入 / 分离 / 播放
  - 上游决策：D-0004、D-0005

## 背景

文件仓库（`docs/architecture.md` §9）尚未实现；播放器需要读取应用目录下的大音频文件，不能放进 SQLite。

## 决策

- 应用文件根：`<userData>/apps/66CCFF/`（曲目、分离结果、引擎）；
- 宿主增加 `media://<appId>/<相对路径>` 协议，按应用 id 映射到 `<userData>/apps/<appId>/`，支持 Range 请求与路径穿越检查；
- 数据库只存相对路径。将来文件仓库实现后再迁移。

## 考虑过、没有采用

- **用 IPC 把音频读成 Blob**：大文件内存 / 传输代价高。
- **放 `app://` UI 目录**：构建产物与用户数据混在一起。
- **`file://`**：从 `app://` 页面加载本地文件受限制。

## 代价

- 目前协议对「哪个应用能读哪个应用的 media 路径」没有内核级权限；作者单机阶段可接受，builder 阶段需要收紧。
- 文件不在文件仓库索引里，删除 / 备份需要应用自己负责。

## 什么时候应该重新考虑

- 实现文件仓库时；
- 引入 builder 或不可信应用时（必须做权限）。
