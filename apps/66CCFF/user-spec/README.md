# 纯蓝（66CCFF）user spec

> 应用 id：`66CCFF`；中文名：纯蓝；英文名：66CCFF。
> 这是作者对纯蓝的预期；技术文档见 [`../docs/README.md`](../docs/README.md)；决策见 [`decisions/`](decisions/README.md)；外部资料线索见 [`../references/README.md`](../references/README.md)。

## 1. 是什么

- 为「学音乐」服务的工具：把一首歌变成可以**分轨、慢放、循环**的练习材料。
- 定位：作者的**扒谱和音乐学习工作台**。
- 作者对纯蓝的需求还比较模糊：学扒谱、分轨、看钢琴卷帘，显示和交互的体验要好；具体设计交给 agent 来做。
- 本质是一层**壳**：替作者完成「分离音轨 + 慢放来听」这一步，不重新发明音频处理。
- 不要求成为音频编辑器；作者没有复杂的可视化需求，先做一版能用的。

## 2. 核心流程与预期

- 导入本地音频文件；
- 分离为**六轨**：人声、鼓、贝斯、其他、吉他、钢琴；使用本机 GPU；
- 内建播放器：分轨音量 / 静音 / 独奏（同一轨的 M 与 S 互斥），慢放（保持音高），循环与 AB 段；
- 空格键暂停 / 继续播放；
- 可选的 MIDI 转写：输入是一条音频，可以是单条 stem，也可以是选定的几条 stem 混合；不把整首歌当输入；输出一个单轨 MIDI；转 MIDI 暂时用 MuScriptor（作者，2026-11-09；已接进应用，见 [66CCFF-0012](decisions/66CCFF-0012-muscriptor-in-app-transcription.md)）；人声旋律用 GAME（作者听了《白石溪》的结果：转得不错，基本可用，2026-11-10；已接进应用，见 [66CCFF-0017](decisions/66CCFF-0017-game-vocal-midi.md)）；
- MIDI 转写的目标是作者在钢琴上学习、弹奏；不要求还原吉他的弦位、指法或六线谱；
- 合唱的歌：如果可以，希望能把每位歌手各自唱的直接转成各自的轨道（作者：《白石溪》的人声事实上是洛天依和乐正绫合唱）；
- 分离有可见的进度与失败原因；
- 可删除曲目。

## 3. 工具与平台

- 不绑定 UVR5 / Audacity；它们只是作者目前工作流的来源，具体引擎由实现选择（见决策）。
- 首版支持 Windows（CUDA）和 macOS（源码安装，分离走 CPU）；不做 Mac 打包分发。设计尽量保持跨平台可替换（路径、引擎命令）。
- 允许应用管理自己的引擎与模型（首次安装 / 下载可以接受）。

## 4. 与 agent

- v1 只要「一键流水线 + 动作可被将来的 agent 调用」，不要求自然语言指挥。
- 不通过模拟点击操作外部软件的 GUI。

## 5. 界面

- 进度 + 内建播放器足够；不要求把外部软件窗口嵌进 MyOutside。
- 播放 / 暂停用图形按钮（播放三角 / 暂停条）表示，不只靠文字。
- 可打开 MIDI 卷帘查看一个或多个 MIDI 文件，并用基础合成器播放；第一版只查看 / 对比，不编辑。
- 钢琴卷帘要能方便地**查看和播放**：作者把钢琴卷帘当谱看。
- 可以两种显示模式都有：从左往右的卷帘，和音符从上往下落到琴键上（作者：电脑屏幕不大，从左往右的话有可能看起来会很小、很难受）。
- 作者用过 GarageBand 的钢琴卷帘，觉得这些都很好（2026-11-10）：左边的琴键；多个轨道；拖动时间戳（播放位置）；缩放和移动——左右和上下都要，**上下很关键**，因为有时候不需要一次看全部的音高，屏幕也放不下；播放时画面跟着走；有乐器音色；有小节。
- 音符块够大时，在块上显示音名（作者：Signal 这样做，很好；肯定是块大小超过某个阈值才显示）。
- **第二种模式是竖着的沉浸式播放**：像音游一样，音符往下落，带小节线，不同乐器用颜色区分，下面是一个钢琴；这种状态不用显示多轨道、乐谱之类，直接就是一个沉浸式的播放模式（作者看了 Midiano：「这太棒了」）。
- 横着的模式，可以考虑在 MIDI 之外同时显示一些其他的东西，例如歌词。
- 要能**同时看几个轨道叠加**的效果，每个轨道最好用不同颜色区分（GarageBand 不顺手的地方：虽然可以有多条音轨，但每次只能把一条放大成左边带琴键的那种大视图，不能同时看几个轨道叠加后的 MIDI）。
- 允许「用系统程序打开文件」作为后路。

## 6. 非目标（v1）

- 音频编辑、降噪、移调、节拍 / 和弦识别、耳训练习、云同步、移动端、导出分享。
- 生成五线谱（作者：暂时没有必要，完全可以把钢琴卷帘当谱看）。
- UVR5 / Audacity 的 GUI 自动化或窗口嵌入。

## 7. 未定

- **转 MIDI 的方案**：单轨还是多轨、分轨后转还是直接转伴奏，都还待定。作者还没仔细分辨产出 MIDI 的质量，原因是还没有一个钢琴卷帘的查看和播放功能来辅助分辨。

- 是否继续评估更强的六轨分离 / 组合方案（当前使用 BS-RoFormer SW 6-stem；旧 `htdemucs_6s` 已弃用，见 [66CCFF-0008](decisions/66CCFF-0008-bs-roformer-engine.md) 和 [`../references/README.md`](../references/README.md)）。
- 是否增加「人声 / 伴奏」两轨快捷预设。
- 是否在应用内提供引擎安装向导（首版用脚本，后续考虑）。
