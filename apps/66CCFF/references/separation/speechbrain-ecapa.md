# SpeechBrain ECAPA-TDNN（说话人识别，用来判断「谁在唱」）

- 最近核对：2026-11-10
- 模型：[speechbrain/spkrec-ecapa-voxceleb](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb)（Apache 2.0，VoxCeleb 训练）；工具包：[SpeechBrain](https://github.com/speechbrain/speechbrain)（Apache 2.0）

## 是什么

**说话人识别**：一段 16kHz 的语音 → 192 维的声音特征（嵌入），同一个人的特征方向相近。本来是给说话用的，不是唱歌。

## 为什么看它

对唱拆成各自一条，分离走不通（[UNMIXX](unmixx.md)、[按参考录音提取指定歌手](singer-informed-separation.md) 都没分开）。换个思路：《白石溪》大多是一人一句，判断「这一刻是谁在唱」比把声音硬分开容易；判断出来后，把 GAME 从整条人声转出的音符分到两个人的轨里。

## 本机验证（Mac，2026-11-10）

- 环境：临时 venv（Python 3.12，speechbrain 1.1.2，PyTorch）。MPS 比 CPU 快约 100 倍（128 个 1.5 秒窗口 0.27 秒；CPU 28 秒）。没有接进纯蓝。
- 参考：作者从网易云下的五首独唱（洛天依三首、乐正绫两首），先用 BS-RoFormer SW 分出人声。参考答案和打分方法见 [按参考录音提取指定歌手](singer-informed-separation.md)「本机验证」（萌娘百科歌词颜色 + LRC 时间，只用来打分）。
- 做法：人声每 0.25 秒取一个 1.5 秒的窗口（太安静的不要）算特征。在参考歌上训练两类线性判别（LDA），每个窗口得一个分数，正 = 天依、负 = 阿绫。沿时间用 Viterbi 平滑（换人要罚分，罚 2 最好）。每个 GAME 音符看它中点那一刻。
- 结果（《白石溪》，只算独唱的字）：
  - 按音符时长：**天依 84%、阿绫 87% 判对**；离换人的地方 0.5 秒以上的音符 96% 判对。错的多在换人的地方，那里参考答案本身的时间也是估的；
  - 按音符个数：天依的 112 个里 97 个对，阿绫的 114 个里 10 个判成了天依；
  - 只比参考的平均特征（余弦相似度）稍差：84%；
  - 在《白石溪》自己的窗口上做两类聚类（从参考出发）**不行**（49%）：聚出来的两类不是两个人；
  - 论文的歌手嵌入 NetSV 更差（交叉验证 41–73%）。
- **两人一起唱的地方（两段副歌，约 98 秒）还分不出来**：
  - MuScriptor 的人声 MIDI 在这些地方只有 4% 的时间有两个不同的音，基本是齐唱；所以这里同一串音符给两个人都对；
  - 但「是不是两人一起」判断不了：分数接近 0 只能弱弱地说明（AUC 0.71–0.73）；拿天依和阿绫参考歌各一段混在一起当「两人一起」的参考，也只认出 16–20%（不同旋律混在一起，和齐唱不一样）；按整句看，副歌句和独唱句的分数也重叠。
- 作者听了：比 UNMIXX 好，但还不可用（见 [想法](speechbrain-ecapa-thoughts.md)）。
- 这条路本身的局限：只判断「谁在唱」，不分离。两人同时唱不同的音（和声）时，GAME 只转一条旋律，另一个人的音就没有了。
- 试听：`~/Downloads/白石溪 MIDI/对唱分离试验/按谁在唱剪开-天依.flac`、`-阿绫.flac`。不是分离，是把人声分轨按判定的时间切给两个人，和下面的 MIDI 用同一套判定（373 个音符全对得上）。
- 结果文件：`~/Downloads/白石溪 MIDI/白石溪-人声分两人-GAME+歌手判定.mid`。两轨 `Luo Tianyi`（199 个音）、`Yuezheng Ling`（174 个音），音符来自 `白石溪-人声-GAME.mid`，速度表和小节线不变；两人一起唱的音被分到其中一个人（84 个到天依、55 个到阿绫）。
