# 围棋（go）

> 作者预期见 [`../user-spec/README.md`](../user-spec/README.md)。9 路特殊规则的双人围棋 + 小聊天窗口 + 悔棋 + 棋谱。规则见 [GO-0001](../user-spec/decisions/GO-0001-9x9-go-capture-loses.md)，联机见 [GO-0002](../user-spec/decisions/GO-0002-go-multiplayer-and-chat.md)，悔棋/棋谱见 [GO-0003](../user-spec/decisions/GO-0003-go-undo-by-request.md)、[GO-0004](../user-spec/decisions/GO-0004-go-records-in-sqlite.md)。

## 1. 规则

- 9×9，黑先；无贴目、无让子、无手数上限。
- 落子、气、提子与普通围棋相同；**任何一颗子被提，对局立即结束**：提子方胜，被提方负，不再点目。
- 自杀非法；占点 / 没轮到 / 对局未开始 / 已结束都拒绝落子，不判负。
- 提子即终局，所以打劫实际上不会发生；不需要劫争规则。
- 没有提子时，连续两次 pass 结束：只数空（围空），不数子。
  - 一块空区只被一种颜色包围 → 全部算该颜色的空；
  - 被双方包围 / 没有包围 → 中立；
  - 棋子本身不计入任何一方；
  - 平台不按目数判胜负，只显示黑空 / 白空 / 中立点。
- 认输：认输方负，对方胜。

## 2. 座位与联机

- 一个 host 只有一个对局；不做房间码/大厅。
- 第一个 `go.join` 的令牌执黑，第二个执白；第三个及以后是只读观战。
- 令牌随机生成，存浏览器 `localStorage`；服务端把令牌与座位写入 `go__player`。刷新、断线、Electron 重启后仍能回到座位。
- 客户端每 500ms 调 `go.getState`；没有 WebSocket/服务端推送。
- 第三人只读：可以看棋和聊天，不能落子或发言。
- 新对局保留座位/黑白，清空棋盘、走子记录和聊天；开局前（0 手）可以交换黑白。
- 认输不要求轮到认输方。

## 3. 悔棋与棋谱

- **悔棋**：请求/同意。请求方撤回自己的上一手以及之后的应手，回到自己落子前；对方可同意/拒绝，请求方可取消。请求未处理时不能落子/Pass；认输/新局/重置可清掉请求。终局后不能悔。
- **棋谱**：每局结束（提子/认输/两次 pass，含 0 手认输）立即归档；进行中的局在“新对局/重置座位”时按 `abandoned` 归档（0 手未开始的不记）。应用内“棋谱”列表 + 回放；不导出 SGF/外部文件，不记录聊天。

## 4. 数据

| 表 | 内容 |
|---|---|
| `go__game` | 单行当前对局：棋盘 JSON、轮次、状态、胜者、结束原因、手数、连续 pass、最后一手、提子信息、目数、已归档标记、待处理悔棋 |
| `go__player` | 座位（black/white）、令牌、入座时间 |
| `go__move` | 走子记录：手数、座位、move/pass、坐标、提子数 |
| `go__chat` | 聊天：座位、文本、时间 |
| `go__record` | 棋谱：结束原因、胜者、手数、走子、每步棋盘快照、目数、提子 |

状态：`waiting`（不足两人）/ `playing` / `finished`。结束原因：`capture` / `two_passes` / `resign` / `abandoned`（棋谱）。

## 5. API

| 函数 | 类型 | 说明 |
|---|---|---|
| `go.getState` | read | 返回棋盘、轮次、状态、结果、目数/归属图、座位、待处理悔棋、最近 100 条聊天 |
| `go.join` | tx | 令牌入座；满员返回 `seat: null`（观战） |
| `go.move` | tx | 落子；校验轮次、占点、自杀、待处理悔棋；提子则终局 |
| `go.pass` | tx | Pass；连续两次则点目结束 |
| `go.resign` | tx | 认输；对方胜；清掉待处理悔棋 |
| `go.newGame` | tx | 归档当前局，重置棋盘/走子/聊天，保留座位 |
| `go.swapColors` | tx | 仅开局前（0 手）交换黑白 |
| `go.resetSeats` | tx | 归档当前局，清空双方座位、棋局、聊天；用于令牌丢失后的重新入座 |
| `go.requestUndo` | tx | 请求撤回自己上一手；对方需同意 |
| `go.acceptUndo` | tx | 对方同意；删除请求方上一手及其后的走子并重放 |
| `go.rejectUndo` | tx | 对方拒绝 |
| `go.cancelUndo` | tx | 请求方取消 |
| `go.archiveFinished` | tx | 兼容旧数据：把已结束但未归档的当前局补进棋谱 |
| `go.listRecords` | read | 最近 100 盘摘要 |
| `go.getRecord` | read | 单盘棋谱：走子 + 每步棋盘快照 |
| `go.sendChat` | tx | 纯文本，1–500 字；仅入座玩家 |

## 6. 界面

- 静态 Canvas 棋盘：木色、坐标 A–J（跳过 I）/1–9、5 个星位、黑白子、最后一手红圈、悬停预览。
- 桌面左右布局（棋盘 + 玩家/结果/悔棋/聊天），手机上下布局。
- 终局归属图：只读半透明方块标出黑空/白空；只在两次 pass 点目后显示。
- 悔棋面板：请求方等待/取消；对方同意/拒绝；请求未处理时棋盘和 Pass 禁用。
- 棋谱弹窗：最近 100 盘摘要，点进后独立 Canvas 回放（上一手/下一手）。
- 聊天窗口：桌面右侧小面板，手机在棋盘下方；显示最近 100 条，自动滚到底部（作者上翻时不打扰）。
- 中英双语，跟随平台 `ui.language`。

## 7. 当前限制

- 不判死活：空区只要边界只出现一种颜色就算该方，即使空区通到棋盘边缘；这是沿用 GoZero `area_ownership` 思路的简化，可能比严格围棋目数大（[GO-0001](../user-spec/decisions/GO-0001-9x9-go-capture-loses.md)「代价」）。
- 无鉴权；只适合可信热点（[D-0071](../../../user-spec/decisions/0071-dev-lan-preview.md)/[GO-0002](../user-spec/decisions/GO-0002-go-multiplayer-and-chat.md)）。
- 悔棋没有超时/次数限制；棋谱只存 SQLite、应用内回放，不导出 SGF；聊天只保留当前对局。
- 计时、AI、SGF 导入导出仍未做。
