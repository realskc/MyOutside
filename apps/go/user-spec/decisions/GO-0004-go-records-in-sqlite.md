# GO-0004 围棋棋谱：存 SQLite，应用内列表 + 回放，不导出外部文件

- 状态：有效
- 日期：2026-10-26
- 决策者：作者
- 服务于：
  - 作者临时需求：保存每一盘的棋谱，之后能回看。
  - 上游决策：[GO-0002](GO-0002-go-multiplayer-and-chat.md)（联机/持久化）

## 背景

作者选择了“应用内棋谱列表 + 回放”，明确不需要导出 SGF/外部文件；保存范围包括正常结束和“新对局/重置座位”中途放弃的对局（只要有落子）。

## 决策

- 每盘结束（提子/认输/两次 pass）时立即写入一条 `go__record`；0 手认输也记录。
- 在“新对局”或“重置座位”时，如果当前局还在进行且有落子，按 `abandoned` 归档后再重置；0 手未开始的对局不记录。
- 记录内容：创建/结束时间、结束原因、胜者、手数、完整走子、每一步之后的棋盘快照、目数、提子信息；**不记录聊天**。
- 应用内“棋谱”按钮打开列表（最近 100 盘），点一条进入回放：
  - 上一手 / 下一手；
  - 显示当前手数、黑白和坐标/Pass；
  - 回放使用独立 Canvas，不干扰当前对局。
- 旧版本留下的“已结束但未归档”的对局：打开棋谱时调用 `go.archiveFinished` 补归档；不归档进行中的对局。
- 不做 SGF 导出、文件下载、外部兼容格式。

## 考虑过、没有采用

- **SGF 导出**：作者明确不需要外部文件；没有采用。
- **只存正常结束的对局**：作者选择“都存”；中途放弃的也归档。
- **只存走子、回放时重算**：可以实现，但每次回放都要重放并处理规则；直接存每步棋盘快照更简单，9×9 数据量很小。
- **聊天一起存**：作者只要求棋谱；没有采用。

## 代价

- 记录存在应用 SQLite 里，不在外部文件；换机器/清数据不会自动带走。
- 列表只显示最近 100 盘；更早的记录仍在库中，但 UI 暂时不列。
- 没有 SGF，不能直接导入其他围棋软件。
- 进行中的对局不会出现在棋谱列表，直到它结束或被新局/重置归档。
- 每步棋盘快照让记录体积比纯走子大，但 9×9 可接受。

## 什么时候应该重新考虑

- 需要备份、导出 SGF、跨设备同步或清理旧记录时。
- 棋谱数量超过 100、需要分页/搜索时。
- 需要记录聊天或对局评论时。
