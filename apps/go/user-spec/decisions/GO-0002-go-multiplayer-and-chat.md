# GO-0002 围棋子应用的联机与聊天：一个对局、令牌入座、500ms 轮询

- 状态：有效（悔棋/棋谱部分见 GO-0003、GO-0004）
- 日期：2026-10-25
- 决策者：agent
- 服务于：
  - 作者临时需求：飞机上和朋友用同一热点联机下 9 路围棋，并带一个小的聊天窗口。
  - 上游决策：[D-0072](../../../../user-spec/decisions/0072-dev-lan-preview.md)（LAN 预览）、[GO-0001](GO-0001-9x9-go-capture-loses.md)（规则）

## 背景

MyOutside 的界面调用统一走 `window.outside.call`，Electron 下是 IPC，LAN 预览下是 HTTP POST。围棋只需要两个玩家、一个对局，不需要账号、房间码或实时推送；玩家可能用手机，刷新/断线后应能回到原来的座位。

## 决策

- **一个 host 只有一个对局**：不做房间码、大厅、多桌。第一个入座者执黑，第二个执白；第三人只读观战。
- **身份**：浏览器生成随机令牌存 `localStorage`；`go.join` 把令牌和座位（黑/白）写入 SQLite。刷新、断线、Electron 重启后，令牌仍能找回座位。
- **状态同步**：客户端每 500ms 调一次 `go.getState`（含棋盘、轮次、结果、最近 100 条聊天）。不做 WebSocket/服务端推送；围棋的回合制节奏足够。
- **持久化**：当前对局、玩家座位、走子记录、聊天都在 SQLite；Electron 重启后继续当前对局。新对局清空棋盘、走子记录和聊天，保留座位和黑白。
- **新局/换色**：任意已入座玩家可以确认后开新局；新局保留黑白。开局前（0 手）可以点“交换黑白”；开局后不允许换色。
- **座位恢复**：令牌丢失时，新客户端会是旁观者；满座时显示“重置座位”，清空双方座位、棋局和聊天，随后双方重新入座。没有鉴权，可信热点内可用。
- **认输**：任意已入座玩家可以认输，对方胜；不要求轮到认输方。
- **聊天**：只有两个入座玩家能发；第三人只读。消息纯文本、最长 500 字，存 SQLite，`getState` 返回最近 100 条；刷新/重启保留，新局清空。聊天窗口在桌面是右侧小面板，手机在棋盘下方，随页面滚动。
- **界面**：Canvas 重画 9×9 木色棋盘（参考 GoZero 的视觉，不搬 PySide6 代码）；桌面左右布局，手机上下布局；坐标 A–J（跳过 I）/1–9；5 个星位；终局归属图只读。
- **不做**：计时、AI、SGF 导出、聊天系统消息、昵称。悔棋与棋谱后来按作者要求补上，见 GO-0003、GO-0004。

## 考虑过、没有采用

- **房间码/多桌**：只有两个玩家、一个 host，增加无用状态；没有采用。
- **WebSocket 推送**：更实时，但当前 `window.outside` 只有 request / response，且围棋不需要毫秒级同步；先用轮询。
- **账号/登录**：LAN 预览没有身份系统，令牌足够区分两个座位；没有采用。
- **第三人禁止进入**：只读观战没有坏处，也方便第三个朋友看棋；没有采用。
- **悔棋**：当时认为双人联机需要双方同意/状态机，和“临时飞机游戏”的复杂度不匹配；后来作者明确要求 B 方案，见 GO-0003。

## 代价

- 没有鉴权：令牌是唯一的座位凭证，知道令牌就能操作该座位；只适合可信热点。
- 500ms 轮询有最多半秒延迟；对围棋无感，但不适合实时游戏。
- 一个 host 只有一个对局，不能同时开多桌。
- 聊天只保留当前对局；新局会清空，不能回看历史聊天。
- 悔棋/棋谱最初没有；GO-0003/GO-0004 补上后，悔棋请求会短暂暂停落子，棋谱存 SQLite。

## 什么时候应该重新考虑

- 要做多桌/房间码、观战聊天、聊天历史或跨设备账号时。
- 需要实时推送、落子音效同步或更低延迟时。
- 要放到不可信网络时，需要鉴权和权限隔离。
- 作者开始需要计时、AI 或 SGF 导入导出时；悔棋/棋谱已由 GO-0003/GO-0004 处理。
