# GO-0003 围棋悔棋：请求对方同意，退回自己上一手

- 状态：有效
- 日期：2026-10-26
- 决策者：作者
- 服务于：
  - 作者临时需求：9 路围棋对局中能悔棋。
  - 上游决策：[GO-0002](GO-0002-go-multiplayer-and-chat.md)（联机机制）

## 背景

作者选择了“请求/同意”的悔棋方式，而不是单方面撤销。悔棋需要处理：悔哪一手、对方已经应手怎么办、请求未处理时能不能继续下、终局后能不能悔。

## 决策

- 已入座玩家可以发“悔棋请求”；对方可以**同意**或**拒绝**；请求方可以**取消**。
- 同意后，撤销请求方的**上一手**，以及这一手之后的所有走子（通常是对方的应手），回到请求方落子前的局面；轮到请求方继续下。
- 请求未处理时：
  - 双方都不能落子或 Pass（`go.move`/`go.pass` 返回 `PRECONDITION`）；
  - 聊天、看棋谱不受影响；
  - 认输、新对局、重置座位仍可用；这些操作会清掉待处理请求。
- 终局后（提子/认输/两次 pass）不能悔棋；没有“复活已结束对局”的入口。
- 没有悔棋次数限制；每次请求都要对方同意。同意后还可以再次请求悔自己的上一手。
- 请求/同意/拒绝/取消都持久化在 `go__game` 的 `undo_*` 列；Electron 重启后仍然有效。

## 考虑过、没有采用

- **A：只能悔自己刚下、对方未应手的一手，无需同意**：简单，但对方一应手就悔不了；作者明确选 B。
- **C：任何人可直接撤销最后一手**：可能撤掉对方的棋，不公平；没有采用。
- **终局后也能悔**：会破坏“提子即终局”的规则，且与棋谱归档冲突；没有采用。
- **超时自动拒绝/自动同意**：会增加一个计时状态，且飞机上可能两边都在操作；先不做。

## 代价

- 请求未处理时对局暂停；如果对方长时间不响应，请求方可以取消，或用认输/新局/重置座位离开。
- 没有超时；恶意或误操作可以反复请求，但只在可信热点内。
- 悔棋后原走子从 `go__move` 删除，棋谱只保留最终保留的走子；被撤销的走子不会出现在记录里。

## 什么时候应该重新考虑

- 需要自动超时、悔棋次数限制或“只能悔最近 N 手”时。
- 需要“终局后复活”或“从任意手回退”时。
- 需要观战者参与/投票时。
