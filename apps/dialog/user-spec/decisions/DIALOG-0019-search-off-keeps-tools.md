# DIALOG-0019 关掉联网搜索时工具定义照常带上：tool_choice = none；开关的变化以 system 消息存进会话

- 状态：有效
- 日期：2026-10-28
- 决策者：作者
- 取代：[DIALOG-0009](DIALOG-0009-web-search-toggle.md) 中「关闭：不给这些工具」的部分
- 服务于：
  - 作者预期：[platform.md「平台 AI」](../../../../user-spec/platform.md)（对话过程中不改动工具定义）
  - 上游决策：[D-0078](../../../../user-spec/decisions/0078-tools-unchanged-within-conversation.md)

## 决策

- 搜索、抓取工具总是交给模型；联网搜索的使用说明也总是在系统提示词里；之前回复里的搜索过程总是放进历史；
- 联网搜索关掉时：请求设 `tool_choice: "none"`（不许调用）；
- 开关的变化**存进会话**（作者要求，以 role = system 的消息）：发一条用户消息时，如果开关和这条消息之前的状态不一样，就在这条用户消息上记下变化（`search_notice`：off / on）；发给模型时，这条用户消息后面跟一条 system 消息——关闭：「用户关闭了联网搜索功能，请不要调用 web_search、web_fetch，直接回答。」（作者的措辞）；重新打开：「用户重新打开了联网搜索功能，需要时可以调用 web_search、web_fetch。」；之后的每一次请求都带着它，模型一直知道开关的状态；开关没变就不再加；
- 会话开始时视为打开；界面上，记了变化的用户消息旁边标「关闭了联网搜索」/「打开了联网搜索」；
- 开关仍然可以在对话中途随时切换，只改变「这一次能不能调用」与历史末尾，不改变对话的前缀。

## 理由

原来关掉开关就不带工具定义、系统提示词里去掉搜索说明、历史里去掉搜索过程：对话中途一切换，缓存几乎全部失效，也让模型困惑（前面明明搜过）。

## 考虑过、没有采用

- 说明只在这一次请求里临时补上、不存进会话：后面的请求就不知道开关关过了，历史也和上一次发的对不上（作者否决）。

## 验证

真实接口（`pnpm ai:check`）：思考模式 + 工具 + `tool_choice: none` 下，对话中途的 system 消息可用，模型按说明回答（「由于你关闭了联网搜索……」）。

## 代价

- 关着的时候每次请求多带一两百 tokens 的工具定义，几乎可以忽略；
- 重新生成一条用户消息的回复时，如果开关和当时不同，这条用户消息上记的变化会改成现在的（之前那条回复是在旧状态下生成的）。
