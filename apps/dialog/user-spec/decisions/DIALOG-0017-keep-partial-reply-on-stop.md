# DIALOG-0017 停止生成或正常关闭时，保存已生成的部分

- 状态：有效
- 日期：2026-10-27
- 决策者：讨论（作者选了方案 C；「一个字都没输出就不保存」是 agent 的建议，作者没有反对）
- 服务于：
  - 作者预期：[对话 user spec「定位」](../README.md)（主力对话工具）
  - 上游决策：[DIALOG-0016](DIALOG-0016-dialog-generation-implementation.md)
- 取代：[DIALOG-0016](DIALOG-0016-dialog-generation-implementation.md) 中「取消时不保存已生成的部分」

## 决策

- **按停止**：已经输出的部分保存为一条回复，标记「已停止」（`message.stopped`），界面在回复上方显示「已停止」；
- **正常关闭 MyOutside**（Cmd+Q、关掉窗口）：退出前把所有进行中的调用当作「按了停止」，最多等 3 秒让它们保存完，再退出；
- **一个字都没输出**（还在思考、或只在搜索还没说话）时停止：不保存，只留用户消息和「生成回复」按钮；
- 停止发生在搜索中：已说的话与搜索过程照常保存（没执行完的搜索记为「已被用户取消」），没有最终回答；
- 保存下来的半截回复和普通回复一样进入之后的对话历史，原样发给模型，不加额外说明；
- 崩溃、强制退出、断电时不保存（需要边生成边存，见下）。

实现要点：
- 平台 AI 的流式请求中途被取消时不报错，返回已收到的部分（`finishReason = "aborted"`；未拼完的工具调用丢弃；拿不到用量）；
- 工具循环把这部分作为最后一轮保留；
- 内核不再因为调用已被取消而拒绝写入：取消只是通知函数「该停了」，停下来之后要不要再保存一次由函数决定。

## 考虑过、没有采用

- 只在按停止时保存（方案 B）：正常关闭也是常见的打断方式，多做一点就能覆盖；
- 边生成边存（方案 D）：能覆盖崩溃与断电，但要处理未写完的草稿、生成中的节点与消息树的交互，写入也多得多；对话回复短、丢了能重新生成，不值得。

## 代价

- 被停止的那一轮拿不到用量，用量统计会少算一点（DeepSeek 照样收费）；
- 退出时如果有生成在进行，最多会晚 3 秒退出。

## 什么时候应该重新考虑

- 回复变得很长、很贵，崩溃或断电造成的损失明显时（考虑边生成边存）；
- 半截回复让模型误以为自己已经说完、影响后续回答时（考虑在历史里加上「回复被中断」的说明）。
