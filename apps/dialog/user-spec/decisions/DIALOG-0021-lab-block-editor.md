- 取代：[DIALOG-0020](DIALOG-0020-laboratory.md) 中「请求体用 JSON 文本编辑器」「v1 不做结构化消息编辑器」的部分

## 决策

- **请求体仍是唯一真相**：块编辑器编辑的就是那个请求体对象，运行时原样交给 `platform.ai.chatRaw`；块只是它的一种显示方式。左栏顶上可以在「块」和「JSON」之间切换，默认「块」，记住上次的选择。
- **三段**：
  - **参数**：除 `messages`、`tools` 以外的所有顶层字段，一行一个；字符串用输入框（`model`、`reasoning_effort`、`tool_choice` 带候选值，仍可随便填）、数字用输入框、布尔用下拉，其余用 JSON 文本框；可以删除、可以添加任意字段（值按 JSON 解析，解析不了就当文本）。
  - **消息**：每条消息一块，左边的色条按 role 区分；块头可以改 role、上移、下移、复制一份、折叠、删除。`content`、`reasoning_content` 用大文本框；assistant 的 `tool_calls` 逐个编辑函数名、调用 ID、参数；tool 消息的 `tool_call_id` 单独一行。块之间悬停可以插入新消息；新加的 tool 消息自动填上前面最近一个还没有结果的调用 ID。
  - **工具**：每个工具一块，编辑名称、说明、参数（JSON Schema）。
- **JSON 里的一切都能改**：
  - 认不得的字段（例如消息上多出来的字段）照样显示，用 JSON 文本框编辑；
  - 任何字段、任何块都可以切到「以 JSON 编辑」，于是可以改成任意类型（例如把 `content` 改成 `null` 或数组）；形状不常规的消息 / 工具（不是对象、多了认不得的结构）直接整块用 JSON；
  - 整个请求体随时可以切到 JSON 文本，和以前一样。
- **写错了不会悄悄发出去**：JSON 文本框和数字框写得不对就标红；有标红的地方时，不能运行，也不能切换视图。
- **删除可以撤销**：删除块或字段后，提示条上有「撤销」。
- 请求体只要求是 JSON 对象；没有 `messages` 也照样发，由 DeepSeek 报错（D-0082：作者做实验时要让 DeepSeek 自己报错）。

## 考虑过、没有采用

- **只做消息的结构化编辑，参数和工具仍用 JSON**：作者要的是整个请求体都更好用。
- **块和 JSON 并排同时显示**：左栏放不下；需要看 JSON 时切过去即可。
- **只支持常规形状，其余报错**：做不到「JSON 中的一切」。

## 代价

- 块编辑器是单独一个文件（`ui/lab-blocks.js`），前端代码多了不少。
- 每次增删、移动都整块重新渲染：消息很多（几百条）时可能有点慢；平时打字只改对象、不重新渲染。
- 写得不对的 JSON 文本框，在增删、移动块之后会恢复成上一次正确的值。

## 什么时候应该重新考虑

- 请求体很大时块编辑器明显卡顿 → 改成只渲染看得见的块，或默认折叠；
- 作者想要的编辑方式超出「块」（例如在消息之间拖拽、批量编辑）；
- 实验室接上自动执行工具或流式之后，块的结构需要跟着变。
