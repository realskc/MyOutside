## 决策

**配方**（`apps/zheye/recipes/`，写法见那里的 `README.md`）

- `<类型>/flow.json` 定义流程：模型、思考强度、草稿的名字、哪份是最终文章、共用的系统提示词文件、按顺序的步骤（名字、提示词文件、最多几轮）；提示词是 Markdown 文件；
- 提示词里可以写 `{{引入 路径}}`（把另一个文件放进来）、`{{变量}}`（讲解对象、类型、今天、流程、这一步、草稿、前置回答）、`<!-- 注释 -->`（不发给模型）；未知变量报错，不把占位符原样发给模型；
- 每次试跑开始时从磁盘读：改了文件不用重启 MyOutside；外壳把配方目录的位置交给哲野的后端（`createZheyeApp({ recipesDir })`）；
- 每次试跑存下当时的配方快照（全部文件的内容）与摘要（8 位），用来对比两次试跑；
- agent 起草的提示词写得很薄，只照搬 user spec（workflow.md「替作者起草提示词」）。

**流程**

- 每一步是一次单独的工具循环：系统提示词 = 共用的文件 + 这一步的提示词；用户消息 = 讲解对象 + 当前全部草稿（程序拼接）；
- 工具：联网搜索、阅读网页、读取 / 查找替换 / 整篇重写草稿，每一步都有、都能改任何一份草稿；
- 试验台暂不询问前置：变量「前置回答」固定为「所有前置都按『正文带过』处理」；
- 机制需要的结构用约定的写法嵌在正文里：直觉的节标题写成 `## [直觉的原话](#断言:直觉的原话)`；文中可点的东西写成 `[文中的文字](#概念:名称)` / `(#断言:原话)` / `(#实体:名称)`；前置清单每行写成 `- P0 概念：名称——为什么需要它`。

**轨迹与存储**

- 两张表：`trial_run`（一次试跑：讲解对象、配方快照、状态、花费、用量）与 `trial_event`（轨迹，按序号递增）；
- 轨迹边跑边存，每条一次短事务：这一步实际发出的提示词（`stage_start`）、工具循环的每一轮（思维链、说的话、工具调用的参数与结果、用量、估算花费）、草稿的每次修改（改完后的全文）、这一步的结束；花费按 D-0074 的价格每轮估算、累加到试跑上，被中断也留得住；
- 发起试跑的页面经推送通道收到实时输出（思维链、正文的增量与工具进度）；其他页面（例如切走再回来）每 1.5 秒按序号取新的轨迹；
- 停止：发起的页面直接取消（立刻停）；其他页面经 `zheye.trialStop`（等这一次模型输出结束才停）；MyOutside 关闭时还在跑的试跑显示「已中断」，已经存下的部分保留；
- 试跑不能删除（以后需要再加）。

## 考虑过、没有采用

- 整个流程一次对话到底：上下文越来越长（搜到的网页都在里面），也看不清每一步各自的提示词；
- 流程写在代码里：作者改流程（增删、调换步骤）就要改代码；
- 提示词打包进程序：改一次就要重新构建、重启 MyOutside。

## 什么时候应该重新考虑

- 加入反复（ZHEYE-0018）、询问前置（ZHEYE-0016）时：流程定义要能表达循环与等待作者；
- 作者觉得配方的写法不顺手时。
