# ZHEYE-0018 写作流程：先走一遍线性流程，大纲不要求结构化，任何一步都能推倒重来

- 状态：有效（未实现；讨论中）
- 日期：2026-10-28
- 决策者：作者（「结构从每一步的产出里读出来」由 agent 提出，作者同意）
- 服务于：
  - 作者预期：[哲野 user spec「工作流与提示词由作者把关」](../README.md)（LLM 始终能推倒重来、大范围修改）

## 决策

- 设想的完整流程：搜集资料 →（拟定大纲 → 分析前置 → 编写文章 → 修改大纲）反复 →（检查文章 → 修改前置、添加前置链接 → 检查文章）反复；
- **现阶段不做反复**，走一遍线性流程，看效果再说：搜集资料 → 拟定大纲 → 分析前置（询问作者，ZHEYE-0016）→ 编写文章 → 检查文章 → 修改前置、添加前置链接。「修改大纲」和最后一次「检查文章」是用来构成反复的，线性流程里不要；
- 大纲有自然语言的要求，三类各不相同；不要求 LLM 交出纯结构化的大纲；
- 不采用「一开始生成结构化大纲，之后的流程都按它走」的设计：每一步都要能推倒重来、大范围修改；
- 机制需要的结构（前置清单、直觉对应的断言、可点的标记）**从每一步的产出里读出来**：大纲是写给下一步看的自然语言；「分析前置」交出一份清单，「修改前置」可以整份重列；节标题与可点的标记用约定的写法嵌在正文里，文章定稿时读出；
- **每一步都能联网搜索**（ZHEYE-0014），开头那一步负责集中搜集；
- 问过作者之后才发现的新前置（写作、检查时冒出来的）**不再询问**：知识库里有记录的按记录处理，已有文章的加链接，其余正文带过；每篇最多问作者一次（作者：暂时这样）。

## 考虑过、没有采用

- 后来发现的新前置再问作者一次：这一篇会第二次停下来等。

## 什么时候应该重新考虑

- 线性流程跑出效果之后（加入反复）；
- 后来发现的 P0 前置经常值得单独讲解时（重新考虑「不再询问」）。
