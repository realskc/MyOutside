# 哲野的配方

> 配方 = 流程 + 各环节的提示词（ZHEYE-0007、ZHEYE-0020、ZHEYE-0021）。由作者把关、设计；目前的内容是 agent 照搬 user spec 起草的薄草稿。

## 目录

```
recipes/
  common/          三类共用：system.md（每一步都带的系统提示词）、quality.md（质量标准）
  concept/         讲解概念：flow.json（流程）+ 各环节的提示词
  assertion/       讲解断言（还没有）
  entity/          讲解实体（还没有）
```

## 流程：`<类型>/flow.json`

```json
{
  "name": "讲解概念",
  "model": "deepseek-flash",
  "reasoningEffort": "max",
  "docs": ["资料", "大纲", "前置", "文章"],
  "article": "文章",
  "system": ["common/system.md"],
  "stages": [{ "id": "research", "name": "搜集资料", "prompt": "concept/1-research.md", "maxRounds": 16 }]
}
```

- `docs`：各步之间传递的草稿；每一步都能用工具读取、查找替换、整篇重写任何一份（ZHEYE-0019）；`article` 是最终的文章；
- `system`：每一步的系统提示词都先放这些文件，再接上这一步自己的 `prompt`；
- `stages`：按顺序执行，每一步是一次单独的工具循环（可以联网搜索、修改草稿）；`maxRounds` 是这一步最多几轮；
- 路径都相对 `recipes/`。

每一步收到的消息：

- 系统提示词：`system` 里的文件 + 这一步的 `prompt`；
- 用户消息：讲解对象 + 当前全部草稿的内容（程序自动拼接，试验台上能看到原文）。

## 提示词里的写法

- `{{引入 common/quality.md}}`：把另一个文件的内容放在这里；
- `{{讲解对象}}`、`{{类型}}`、`{{今天}}`、`{{流程}}`（各步的名字）、`{{这一步}}`、`{{草稿}}`（草稿的名字）、`{{前置回答}}`（作者对前置的回答；试验台暂不询问，全部按「正文带过」）；
- `<!-- … -->`：注释，只给人看，不发给模型。

## 改了之后

保存文件即可：下一次试跑就用新内容，不用重启 MyOutside。每次试跑都会存下当时的配方快照，可以在试验台上对比两次试跑用的配方有什么不同。
